1 IPv4 and IPv6

IP stands for Internet Protocol. It identifies addresses and delivers packets across networks, and it sits at the Network layer of the OSI model. An IP address is assigned to an interface, not to a whole device, so one device can have several IP addresses. IP is a best-effort service: it does not guarantee that data arrives, arrives complete, or arrives in order.

TopicIPv4IPv6
Address size32 bits128 bits
Total address space2^32 ≈ 4.29 billion2^128 ≈ 3.4 × 10^38
FormatFour decimal numbers separated by dotsEight hexadecimal groups separated by colons
Example192.168.1.102001:db8::10
Size of each part8 bits, values 0–25516 bits, values 0000–ffff
BroadcastYesNo — multicast covers many of those jobs
Finding neighbors on the linkARPNeighbor Discovery over ICMPv6

These numbers are the mathematical totals, not the number of addresses that can actually be handed out as public addresses. IPv6 is not automatically faster or more secure than IPv4; real-world results depend on the path, the equipment, and the configuration.

Say it: "The main difference is address size — IPv4 is 32 bits and IPv6 is 128 bits. IPv6 also drops broadcast, uses Neighbor Discovery instead of ARP, and supports SLAAC, so hosts can configure their own addresses."

Reading IPv4 addresses and prefixes

192.168.1.10/24 means the network part is 24 bits long, leaving 8 bits for hosts. The subnet mask is 255.255.255.0. For this subnet, the network address is 192.168.1.0 and the broadcast address is 192.168.1.255. Usable host addresses are .1 through .254 — 254 addresses in total.

The formula 2^(host bits) − 2 works for ordinary IPv4 subnets, but there are exceptions, such as /31 for point-to-point links and /32 for a single address. Don't subtract two when working with IPv6.

IPv4 ranges to knowMeaning
10.0.0.0/8Private
172.16.0.0/12Private, from 172.16.0.0 to 172.31.255.255
192.168.0.0/16Private
127.0.0.0/8Loopback, e.g. 127.0.0.1
169.254.0.0/16Link-local — often seen when a host configures itself after failing to get a DHCP lease

Private IP addresses are used internally and are not routed directly on the public internet. A typical home router uses NAT/PAT so that many devices can share one public IPv4 address. NAT is not the same thing as a firewall.

Reading and shortening IPv6 addresses

Full example: 2001:0db8:0000:0000:0000:0000:0000:0010

  1. Drop leading zeros in each group: 0db8 becomes db8, and 0010 becomes 10.
  2. Replace one run of consecutive all-zero groups with :: — only once per address.
  3. So it can be written as 2001:db8::10. When you expand it again, you must end up with eight groups.

Never drop trailing zeros (1200 is not 12), and never use :: twice — otherwise you can't tell how many zero groups each one stands for.

IPv6 addresses to knowMeaning
::1Loopback
::Unspecified address
fe80::/10Link-local — valid on one link only; routers don't forward it
fc00::/7Unique Local Address (ULA)
ff00::/8Multicast
2001:db8::/32Reserved for documentation examples

IPv6 LANs usually use a /64, especially with SLAAC, but not every IPv6 network must be a /64. Dual stack means running IPv4 and IPv6 side by side. The two versions cannot talk to each other directly without a helper mechanism such as translation.

More detail: IPv6 has a 40-byte base header and uses extension headers for extra information. Routers along the path do not fragment IPv6 packets; if fragmentation is needed, the sender does it, usually relying on Path MTU Discovery to size its packets. Reference: RFC 8200

2 Multicast and delivery types

TypeReceiversExample idea
UnicastA single destinationA client connecting to a web server
BroadcastEvery host in the broadcast domainAn ARP request on a typical IPv4 Ethernet
MulticastMembers of a specific groupDistributing a stream to a group of receivers on a network that supports it
AnycastOne destination out of several that share an addressPicking a service location based on routing metrics

Multicast sends to a group address. Network devices that support it make copies along the path toward members, which reduces duplicate traffic from the sender compared with opening a separate unicast stream for everyone. It does not go to every host, and it does not guarantee that every member receives the data.

  • IPv4 multicast uses 224.0.0.0/4, i.e. 224.0.0.0–239.255.255.255.
  • IPv6 multicast uses ff00::/8.
  • IGMP manages multicast group membership for IPv4; IPv6 uses MLD, which runs over ICMPv6.
  • Crossing routers requires multicast routing to be supported and configured. It does not work across the internet automatically.
  • For anycast, "nearest" means nearest by routing, not necessarily nearest geographically.

Example: with 100 viewers, unicast may require the sender to send 100 streams. Multicast can send into a shared distribution tree and copy the data only where the path branches toward receivers — provided the infrastructure supports it.

Say it: "Unicast is one-to-one, broadcast is one-to-all on the local segment, multicast is one-to-many for subscribed members, and anycast is one-to-nearest by routing. IPv6 has no broadcast."

3 Hexadecimal

Hexadecimal, or hex, uses 16 symbols: 0–9 and A–F. Upper and lower case mean the same thing. A=10, B=11, C=12, D=13, E=14, and F=15.

One hex digit represents 4 bits, so two digits represent one byte and four digits represent 16 bits. The 0x prefix just marks a number as hexadecimal; it is not part of the value.

Hex to decimal

Use the place values 16^0, 16^1, 16^2 … from right to left.

  • 2F = (2 × 16) + 15 = 47
  • FF = (15 × 16) + 15 = 255
  • 1A3 = (1 × 256) + (10 × 16) + 3 = 419

Decimal to hex

Divide by 16 repeatedly and read the remainders from last to first. For example, 254 ÷ 16 = 15 remainder 14, so the answer is FE, because 15 = F and 14 = E.

Binary to hex

Split the bits into groups of four starting from the right, padding the leftmost group with zeros if needed. For example, 11000000 becomes 1100 0000, which is C0 — 192 in decimal.

Networking connection: one IPv6 group has up to 4 hex digits, which is 16 bits; eight groups make 128 bits. A 48-bit MAC address is usually written as six hex pairs, such as 02:1A:2B:3C:4D:5E. Being written in hex doesn't mean something is an IPv6 address.

4 How DNS works behind the scenes

DNS, the Domain Name System, is a distributed, hierarchical naming system used to look up records for a name — for example, translating a website name into an IPv4 or IPv6 address. DNS does not download the web page, and one name can map to several addresses.

What happens when you open https://www.example.com

  1. The browser and the operating system may check their caches or local name sources, depending on configuration.
  2. If there is no answer yet, the host's stub resolver sends the query to the configured recursive resolver, such as one run by the company or the ISP. Some browsers may use their own resolver over DoH.
  3. If the recursive resolver has a valid cached answer, it returns it immediately.
  4. If not, the resolver starts by asking a root server, which refers it to the .com servers.
  5. The .com (TLD) server refers it to the authoritative name server for example.com.
  6. The authoritative server answers with the record for www.example.com. If it's a CNAME alias, the resolver may have to follow it to the target name.
  7. The resolver caches the answer according to its TTL and returns it to the client.
  8. The browser uses the address to connect to the server, then continues with TLS and HTTP as the protocol requires.

The root → TLD → authoritative sequence describes the case where caches don't help. In practice, many steps are skipped because the data is already cached. Naming and resolver concepts in RFC 1034

Say it: "First the browser checks its local cache. If it misses, the stub resolver asks a recursive resolver. On a cache miss, the resolver walks the hierarchy — root, then the TLD, then the authoritative server — caches the answer for the TTL, and returns the IP address. Then the browser opens the connection and does the TLS handshake."

Who does what

ComponentRole

A recursive query asks the server to get the final answer (or return an error). An iterative query may return either an answer or a referral to another server to ask next.

Record types and key terms

TTL is how long a record may be cached — not how long a DNS packet takes to travel. DNS changes may not show up everywhere at once because each cache has a different amount of TTL left. Classic DNS uses both UDP and TCP on port 53, not just UDP.

DNSSEC uses signatures to verify that DNS data is authentic and unmodified, but it does not encrypt queries. DoH and DoT encrypt DNS traffic in transit; they do not replace DNSSEC.

Troubleshooting: if a site won't open by name but the network can still reach other destinations, DNS may be the problem. Opening an HTTPS site by its IP address is not a complete substitute test, because certificates and virtual hosting may need the domain name.

5 Network topology

Topology is the way devices are connected. Physical topology is how things are actually wired; logical topology is how data flows. The two don't have to match.

TypeStructureAdvantagesLimitations and weak points
MeshDevices connect through multiple pathsRedundant paths; tolerates some link failuresNeeds many links and ports; complex to manage
StarEvery device connects to a central pointEasy to add devices and isolate problemsIf the center fails, every device that depends on it is affected
BusDevices share a common backbone cableSimple structure for small legacy setupsA backbone fault takes down the whole segment; collisions on shared Ethernet
RingDevices are linked in a loopSome systems control access to transmit in an orderly wayA break in a basic ring can stop the whole ring; needs a backup mechanism

Mesh

In a full mesh, every node has a direct link to every other node. With n nodes and one bidirectional link per pair, you need n(n−1)/2 links. For example, 5 nodes need 10 links, and each node connects to 4 others. A partial mesh connects only some pairs to reduce cost, so the full-mesh formula doesn't apply to every mesh.

Star

Common in switched Ethernet LANs. A failed device or cable usually affects only that device, but if the central switch fails, every device connected to it may be affected. Real networks often have redundant cores and backup paths.

Bus

Old coaxial Ethernet used a shared cable with terminators at each end. Bad termination could cause signal reflections. This is very different from today's switched, full-duplex Ethernet.

Ring

Each node connects to its neighbors in the loop. Token Ring used a token to control who could transmit, but not every ring-shaped technology uses a token or only sends in one direction. Dual rings or protection mechanisms can add resilience.

Common trick question: a hub-based network can be a physical star but logically a shared medium. A star-shaped diagram doesn't prove there are no collisions — you have to look at the devices and the duplex mode.

6 HTTP and HTTPS

HTTP is an Application-layer request/response protocol — for example, requesting a web page or sending data to an API. HTTPS is HTTP carried over a connection protected by TLS.

TopicHTTP without TLSHTTPS
URL schemehttp://https://
Default port80443
ConfidentialityNone from HTTP itselfTLS encrypts data between the TLS endpoints
Tamper detectionNo TLS protectionTLS detects modification in transit
Server authenticationNo TLS certificateUses a certificate, checking the name and the chain of trust

These ports are defaults; other ports can be used. HTTPS protects the communication, but it does not guarantee that the site owner is trustworthy or that the content is safe. HTTP and HTTPS in RFC 9110

The process, simplified

After DNS returns an IP address, for HTTP/1.1 or HTTP/2 over HTTPS the client usually opens a TCP connection, then performs a TLS handshake: it checks the certificate, agrees on keys, and then exchanges HTTP inside the encrypted channel. Details differ when a connection is reused or a session is resumed. HTTP/3 runs over QUIC on UDP with TLS 1.3 built in, so don't memorize "HTTPS always uses TCP."

TLS protects HTTP content — the path, query string, headers, and body — between the TLS endpoints. A network observer may still see IP addresses, packet sizes and timing, and name information from DNS or the connection setup, depending on privacy settings.

Say it: "HTTPS is just HTTP over TLS. TLS gives you three things: confidentiality through encryption, integrity so tampering is detected, and server authentication through certificates. It doesn't tell you whether the site itself is trustworthy."

Terms to remember

  • GET retrieves data; POST sends data for the server to process according to the application's rules.
  • 200: OK, 301/302: redirect, 404: not found, 500: server error.
  • HTTP is stateless at the protocol level. Applications use cookies or tokens to tie requests to a user's state.
  • HTTP and HTTPS both live at the Application layer. HTTPS is not "OSI layer 8."

7 The OSI model in detail

OSI is a seven-layer reference model that helps divide responsibilities and troubleshoot problems. The real internet uses the TCP/IP suite, which doesn't always split cleanly into seven separate modules — Session and Presentation in particular are usually handled inside applications or libraries.

Overview, top to bottom

LayerNameMain jobCommon teaching PDUExamples
7ApplicationNetwork services used by applicationsDataHTTP, DNS, SMTP
6PresentationData format, encryption, compressionDataEncoding and serialization
5SessionManaging dialogs and synchronization pointsDataOpening, maintaining, and closing a dialog
4TransportProcess-to-process delivery; separates services by portTCP segment / UDP datagramTCP, UDP
3NetworkLogical addressing and routing between networksPacketIPv4, IPv6, routers
2Data LinkDelivering frames on a link using MAC addressesFrameEthernet, Wi-Fi MAC, switches
1PhysicalSending bits as signals over a mediumBitsCopper, fiber, radio

PDU stands for Protocol Data Unit — the name for a unit of data in a given protocol. The names in the table are the ones commonly used in teaching, not the only correct names in every context.

Memory aid (top to bottom): All People Seem To Need Data Processing. Bottom to top: Please Do Not Throw Sausage Pizza Away.

Layer 7 — Application

Provides network services to applications: HTTP for the web, DNS for name lookups, SMTP for sending email. "Application layer" doesn't mean the program's whole user interface; it means the application-level communication functions.

Example symptom: a website returns 404. That means an HTTP response came back, so don't jump to the conclusion that the cable is unplugged. The cause may be the path or the web server's configuration.

Layer 6 — Presentation

Makes sure both ends interpret data the same way: character encoding such as UTF-8, data structure conversion, and compression. Textbooks often discuss encryption at this layer, but TLS in real TCP/IP stacks shouldn't be rigidly classified as Layer 6.

Example symptom: text shows up as garbled characters, or a program can't parse a data format. That may be an encoding or format agreement issue.

Layer 5 — Session

Handles starting, maintaining, and ending a dialog between systems, including synchronization and resume points where supported. A web "login session" is usually handled at the application level; it doesn't prove there's a separate Layer 5 protocol.

Example: conferencing or other dialog-based services may need to keep context between the parties, but you should look at the actual protocol before mapping it to OSI.

Layer 4 — Transport

Uses ports to distinguish processes or services on the same host. For example, a client uses a temporary (ephemeral) source port to connect to destination port 443.

TCPUDP
Connection-oriented; delivers a byte streamSends individual datagrams
Sequence numbers, acknowledgements, and retransmissionUDP itself doesn't guarantee delivery or ordering
Flow control and congestion controlThe application handles anything extra it needs
Good when you need complete, in-order dataGood when the application wants to design its own delivery behavior

TCP doesn't guarantee that the receiving application processed the data successfully, and UDP is not "always faster." QUIC provides reliable streams on top of UDP — a good example of why you should separate UDP's own properties from the protocols built on it.

Say it: "TCP is connection-oriented and reliable — it has a three-way handshake, sequence numbers, acknowledgements, and retransmission. UDP is connectionless and lightweight, so it's used for things like DNS, streaming, gaming, and QUIC, where the application handles reliability itself."

Layer 3 — Network

Uses IP addresses and a routing table to choose the next hop. If the destination is outside the subnet, the host normally sends to its default gateway. Routers read the destination IP and forward the packet along the best path. The IPv4 TTL or IPv6 Hop Limit decreases at each hop, which prevents packets from looping forever.

Example problems: a wrong subnet mask, no default gateway, or no route to the destination. Routers mainly work at Layer 3, but real devices may also do firewalling or other layers' jobs.

Layer 2 — Data Link

Packages data into frames for a link. Ethernet uses MAC addresses and an FCS for error detection. A switch learns which source MAC addresses are on each port and uses the destination MAC to pick the outgoing port. For unknown unicast, it may flood the frame within the VLAN.

VLANs split a Layer 2 network into separate broadcast domains, so being in the same building doesn't mean being in the same subnet or VLAN. Layer 3 switches can also route.

Layer 1 — Physical

Electrical, optical, and radio signals; cables, connectors, distance limits, and data rates. Typical devices at this layer are repeaters and hubs. Common problems include loose cables, no link light, or interference.

Encapsulation and decapsulation

Sender: application data → TCP segment or UDP datagram → IP packet → frame → signal

Receiver: signal → frame → IP packet → transport data → application data

Each layer adds control information — a header, and at some layers a trailer. The receiver reads and removes them in order. A router along the way strips the incoming frame, processes the IP packet, and builds a new frame for the outgoing link; it doesn't need to read the application data to route.

Example: reaching a website on another network

Suppose the PC is 192.168.1.10/24, the gateway is 192.168.1.1, and the example web server is 203.0.113.20.

  1. The PC sees that the web server's IP is outside its subnet, so it chooses the gateway as the next hop.
  2. The PC uses ARP to find the gateway's MAC address if it isn't already cached.
  3. The IP packet's destination IP is the web server, but the Ethernet frame's destination MAC is the gateway.
  4. The router forwards the packet and rewrites the Layer 2 header for the next link.
  5. The destination IP usually stays the same along the whole path, although NAT and some other mechanisms can change addresses or ports.

203.0.113.20 is a documentation address, not a real website to test against.

Say it: "MAC addresses get the frame across one link, IP addresses get the packet across networks, and ports get the data to the right application. When you leave your subnet, the destination IP is the server, but the destination MAC is your default gateway."

Some courses use a five-layer TCP/IP model that separates out Physical, so check which version is expected.

A troubleshooting approach for scenario questions

  1. Physical: is there a link light, or is Wi-Fi connected?
  2. Data Link: is the port and VLAN correct? Can you reach neighbors on the link?
  3. Network: are the IP, prefix, gateway, and routes correct?
  4. Transport: can you reach the required port? Is a firewall blocking it?
  5. Upper layers: does DNS answer? Is the TLS certificate valid? What does the application return?

Ping uses ICMP, not TCP or UDP. A failed ping doesn't always mean the host is down — ICMP may be filtered. And a successful ping doesn't confirm that the website or port 443 is working.

Say it: "I'd troubleshoot bottom-up: check the physical link first, then the VLAN and Layer 2 connectivity, then IP settings and the gateway, then whether the port is reachable, and finally DNS, the certificate, and the application's response."

8 LAN and WAN

TopicLANWAN
Full nameLocal Area NetworkWide Area Network
ScopeA limited area such as a home, office, or buildingConnects networks across distances, e.g. branches or countries
Operated byMainly one person or organizationMay involve the organization and several service providers
Example technologiesEthernet and Wi-FiProvider links, leased lines, or branch connectivity services
PerformanceUsually low latency over short distancesLatency depends on distance and path

Speed is not the deciding factor between LAN and WAN — a high-speed WAN can be faster than some LANs. The internet is a global network of networks and is often used as the basic example of a WAN.

Example: home connecting to a company

Home devices → switch or access point → router → ISP network and the internet → company router → company LAN

  • The LAN ports on a home router usually connect internal devices; the WAN port is the uplink to the provider's network.
  • Wi-Fi is a wireless connection technology, not the internet. You can be connected to Wi-Fi and still have no internet.
  • A LAN still works internally without the internet — for example, file sharing or printing to a printer on the same network.
  • A single home router usually combines several roles: router, switch, access point, DHCP server, and NAT.
  • Public/private IP is not the same as WAN/LAN. The WAN side may get a private address or sit behind the provider's CGNAT.

9 End-to-end communication

End to end means looking at the whole journey between the two systems that are really talking, such as your browser and a web server. Everything in between — switches, routers, ISPs — only helps carry the data. The opposite idea is hop by hop, which covers one link at a time.

End to endHop by hop
ScopeSource to final destinationOne link to the next device
ExamplesTCP, TLS, HTTPEthernet frames, Wi-Fi
AddressesIP addresses and ports (unless NAT changes them)MAC addresses change on every link
Who reads itThe two endpointsThe device on each link

The full journey of one web request

  1. Get an address: the host already has an IP, a mask, a gateway, and a DNS server, usually from DHCP.
  2. Resolve the name: DNS turns www.example.com into an IP address.
  3. Choose the next hop: the destination is outside the subnet, so the host sends to its default gateway and uses ARP to find the gateway's MAC.
  4. Open the connection: TCP does its three-way handshake to port 443, then TLS checks the certificate and agrees on keys.
  5. Send the request: the HTTP request is encrypted and wrapped into TCP, IP, and an Ethernet frame.
  6. Cross the network: the switch forwards by MAC. The home router applies NAT, and each router forwards by IP, lowers the TTL, and builds a new frame.
  7. Reach the server: the server removes each layer, and the port delivers the data to the web service.
  8. Send the response: the reply returns with source and destination swapped. The return path can differ from the outgoing path, and NAT translates the address back.

Why it matters: the end-to-end principle says that features such as reliability and encryption work best at the endpoints, because only they know whether the job really succeeded. That is why routers can stay simple and TCP and TLS run on the hosts.

Say it: "End to end means the whole path between the two systems that are communicating. TCP and TLS work end to end, so only the client and server use them. Ethernet works hop by hop, so the MAC addresses change on each link while the IP addresses normally stay the same."

10 TCP three-way handshake

Before TCP sends application data, both sides must agree that a connection exists and share their starting sequence numbers. The three-way handshake does this in three messages.

  1. SYN: the client says, "I want to connect, and my sequence numbers start at x."
  2. SYN-ACK: the server replies, "I received x, so I expect x+1 next. My sequence numbers start at y."
  3. ACK: the client replies, "I received y, so I expect y+1 next." The connection is now established on both sides.

Why three messages, not two?

TCP carries data in both directions, so each side must have its own sequence number confirmed. Two messages would confirm only the client's number. The third message confirms the server's number, and it also helps the server ignore old, delayed connection requests.

What the failures tell you

What you seeLikely meaning
Connection refused (RST reply)The host was reached, but nothing is listening on that port, or a firewall rejected it
Connection timed out (no reply)A firewall dropped the SYN, the route is broken, or the host is down
Many half-open connections on the serverPossibly a SYN flood attack; SYN cookies help protect against it

Closing a connection: each direction closes separately, usually with FIN, ACK, FIN, ACK. This is often called the four-way close. The side that closes first then waits in TIME-WAIT in case any late packets arrive.

Say it: "The client sends a SYN with its sequence number. The server answers with a SYN-ACK, which acknowledges that number and sends its own. The client then sends an ACK, and the connection is established. It takes three steps because both sides need their sequence numbers confirmed."

11 Connecting a fiber link to a copper switch

Short answer: use a media converter. It takes light from the fiber on one side and outputs electrical Ethernet on an RJ45 port on the other side. Then a normal copper patch cable connects it to the switch.

What must match

CheckWhy
Fiber typeSingle-mode and multi-mode optics are not interchangeable; match the transceiver to the fiber
Wavelength and distanceBoth ends need compatible optics, and the rating must cover the distance (e.g. 850 nm for short multi-mode, 1310 nm for longer single-mode)
SpeedBoth ends of the fiber must run the same speed; 1G and 10G optics usually won't link
ConnectorUse the right type, such as LC or SC; a patch cord can adapt between them
Tx and RxWith two strands, Tx at one end must reach Rx at the other. If there is no link, swap the strands
Copper sideUse Cat5e for 1G or Cat6A for 10G, up to 100 m, and make sure the switch port supports that speed

If the switch has an SFP or SFP+ slot, it is usually cleaner to plug in a matching module instead of adding a separate box with its own power supply. Check that the switch vendor supports that module, because some switches reject third-party optics.

This is a Layer 1 change. The media converter doesn't need an IP address or any configuration in the basic case, and Ethernet frames and IP stay the same.

Say it: "Fiber uses light and copper uses electrical signals, so I'd use a media converter between them, then a patch cable to the switch. If the switch has an SFP slot, I'd use a module instead. Either way, I'd match the fiber type, wavelength, speed, and connector."

12 Letting hosts reach your server

Think of it as a chain: the service must be running, the server must be reachable, and every firewall on the way must allow the port. Then you test from outside the server, not from the server itself.

Step by step

  1. Run the service and check that it starts at boot.
  2. Check the listening address. A service on 127.0.0.1 accepts only local connections. Use 0.0.0.0 or the server's own IP so that other hosts can connect.
  3. Give the server a stable IP with a static address or a DHCP reservation, so that its address doesn't change.
  4. Open only the ports you need on the server's firewall, such as 80 and 443. Allow SSH first if you manage the server remotely, or you may lock yourself out.
  5. Make a network path. On the same subnet, hosts connect directly. From another subnet, routing and internal firewalls must allow it. From the internet, you need a public IP plus port forwarding on the router, or a cloud security group rule.
  6. Add DNS by creating an A or AAAA record that points the name at the public IP.
  7. Enable HTTPS with a TLS certificate, such as one from Let's Encrypt.
  8. Test from a real client, ideally on another network such as a phone on mobile data.

Example on Debian with nginx

# On the server
sudo apt update && sudo apt install nginx ufw
sudo systemctl enable --now nginx
sudo ss -tlnp | grep ':80'          # Is it listening, and on which address?

sudo ufw allow OpenSSH              # Do this before enabling ufw
sudo ufw allow 80,443/tcp
sudo ufw enable

# From another host
curl -I http://192.168.1.50
nc -vz 192.168.1.50 80

Security: avoid exposing SSH or databases to the whole internet. Use SSH keys, restrict management ports to a VPN or trusted IPs, and keep the system updated.

Say it: "First I'd confirm that the service is running and listening on the right address. Then I'd give the server a stable IP and open only the required ports on its firewall. For internet access, I'd set up port forwarding or a cloud security rule, add a DNS record, enable HTTPS, and test from an outside network."

Interview practice — quick questions

Try answering out loud before opening each answer.

1. How long is an IPv6 address, and how many bits does one hex digit represent?128 bits, and each hex digit represents 4 bits.
2. Shorten 2001:0db8:0000:0000:0000:0000:0000:0001.2001:db8::1 — the :: replaces six zero groups.
3. Convert hex 3A to decimal.58, because (3 × 16) + 10 = 58.
4. Convert decimal 192 to hex.C0, because 12 × 16 = 192.
5. How many links does a full mesh of 6 nodes need?15 links, because 6 × 5 ÷ 2 = 15.
6. What do you call sending data only to members of a group?Multicast.
7. Which DNS record returns an IPv6 address?AAAA.
8. Do root DNS servers store the IP address of every website?No. Their main job is to refer resolvers to the right TLD servers.
9. Why do some users still see the old answer after a DNS change?Their resolver's cache hasn't expired yet — the old record's TTL is still running.
10. Which OSI layers do a typical switch and a router mainly work at?A switch works at Layer 2 and a router at Layer 3, although real devices may handle several layers.
11. When sending outside the subnet, does the first frame carry the web server's MAC address?No. It carries the MAC of the next hop, such as the default gateway. The destination IP is still the web server.
12. Does HTTPS guarantee that a website isn't a scam?No. TLS protects the connection and verifies identity according to the certificate, but it says nothing about whether the site is honest.
13. Does UDP retransmit lost data automatically?Not in UDP itself. An application or protocol built on UDP, such as QUIC, can add that.
14. Does a LAN need internet access?No. A LAN can still provide internal services without the internet.
15. Are 192.168.1.10/24 and 192.168.2.10/24 on the same subnet?No. With a /24 they're on different subnets, so they need routing to communicate.
16. If ping works, does that guarantee HTTP works?No. ICMP getting through doesn't confirm that the web service or the required port is open.
17. Does IPv6 have broadcast?No. It uses multicast for many of the jobs that used to rely on broadcast.
18. Which OSI layers does the four-layer TCP/IP Application layer combine?Layers 5, 6, and 7.

Common open-ended interview questions

What happens when you type a URL into the browser and press Enter?

"First the browser parses the URL and checks its caches. If it doesn't have the address, it resolves the hostname through DNS — the local resolver asks a recursive resolver, which may walk from the root to the TLD to the authoritative server, and returns an A or AAAA record. Then the browser opens a connection to that IP on port 443 — usually TCP, or QUIC for HTTP/3 — and does a TLS handshake, verifying the server's certificate. Once the secure channel is up, it sends an HTTP GET request, the server responds with HTML and a status code, and the browser parses it, fetches additional resources like CSS and JavaScript, and renders the page."

Explain the difference between TCP and UDP.

"TCP is connection-oriented. It sets up a connection with a three-way handshake and guarantees reliable, in-order delivery using sequence numbers, acknowledgements, and retransmission, plus flow and congestion control. UDP is connectionless — it just sends datagrams with no delivery or ordering guarantees, so it has less overhead. I'd choose TCP for things like web pages or file transfers, and UDP for DNS queries, real-time voice or video, or games, where low latency matters more than every packet arriving."

What is the difference between a switch and a router?

"A switch forwards frames within a local network using MAC addresses — that's Layer 2. A router forwards packets between different networks using IP addresses and a routing table — that's Layer 3. In practice, a Layer 3 switch can do both, and a home router usually combines a router, a switch, a Wi-Fi access point, DHCP, and NAT in one box."

What is a subnet mask, and why do we use subnets?

"A subnet mask tells you which part of an IP address is the network and which part is the host. For example, /24 or 255.255.255.0 means the first 24 bits are the network. Subnetting lets us split a big network into smaller broadcast domains, which improves performance, makes security policies easier to apply, and uses address space more efficiently."

What is NAT, and is it a security feature?

"NAT — Network Address Translation — rewrites addresses as traffic passes through a router, usually so that many devices with private IPv4 addresses can share one public address. It does hide internal addresses, but it isn't a firewall. Security should come from proper firewall rules, not from NAT alone."

A user says "the internet is down." How would you troubleshoot it?

"I'd go layer by layer. First, check the physical connection — the cable, link light, or Wi-Fi association. Then check whether the device has a valid IP address, subnet mask, and gateway — a 169.254 address would suggest a DHCP problem. Next, ping the gateway, then a public IP, to see where connectivity stops. If IPs work but names don't, it's likely DNS. Finally, if a specific site fails, I'd check the port, the firewall, the certificate, and what the application actually returns."

Suggested review order

Start by memorizing the OSI table and the difference between MAC, IP, and port → practice IPv4/IPv6 and hex → explain DNS in your own words, out loud → compare topologies, HTTP/HTTPS, and LAN/WAN → answer the questions with the answers closed, then revisit any topic you got wrong.
