1 IPv4 และ IPv6

IP ย่อมาจาก Internet Protocol ทำหน้าที่ระบุที่อยู่และส่งแพ็กเก็ตข้ามเครือข่าย อยู่ในชั้น Network ของ OSI ที่อยู่ IP โดยหลักผูกกับอินเทอร์เฟซของอุปกรณ์ อุปกรณ์หนึ่งจึงมีหลาย IP ได้ IP เป็นบริการแบบ best effort ไม่รับประกันว่าข้อมูลจะถึง ครบ หรือตามลำดับ

ประเด็นIPv4IPv6
ขนาดที่อยู่32 บิต128 บิต
จำนวนที่อยู่ทางคณิตศาสตร์2^32 ประมาณ 4.29 พันล้าน2^128 ประมาณ 3.4 × 10^38
รูปแบบเลขฐานสิบ 4 ชุด คั่นด้วยจุดเลขฐานสิบหก 8 กลุ่ม คั่นด้วย colon
ตัวอย่าง192.168.1.102001:db8::10
ขนาดแต่ละชุด8 บิต ค่า 0–25516 บิต ค่า 0000–ffff
Broadcastมีไม่มี ใช้ multicast ในหลายหน้าที่แทน
การหาเพื่อนบ้านบนลิงก์ARPNeighbor Discovery ผ่าน ICMPv6
การตั้งค่าManual หรือ DHCPManual, SLAAC และ/หรือ DHCPv6
NATใช้แพร่หลายเพื่อแบ่งใช้ IPv4 สาธารณะโดยทั่วไปไม่จำเป็นเพื่อแก้ปัญหาที่อยู่ขาดแคลน

จำนวนที่อยู่ข้างต้นเป็นจำนวนทั้งหมดทางคณิตศาสตร์ ไม่ใช่จำนวนที่นำไปแจกเป็น public address ได้ทั้งหมด IPv6 ไม่ได้เร็วกว่า IPv4 หรือปลอดภัยกว่าโดยอัตโนมัติ ผลจริงขึ้นกับเส้นทาง อุปกรณ์ และการตั้งค่า

อ่าน IPv4 และ prefix

192.168.1.10/24 หมายถึงส่วนเครือข่ายยาว 24 บิต เหลือส่วน host 8 บิต Subnet mask คือ 255.255.255.0 สำหรับ subnet นี้ network address คือ 192.168.1.0 และ broadcast address คือ 192.168.1.255 ที่อยู่ host แบบทั่วไปใช้ได้ .1 ถึง .254 รวม 254 ที่อยู่

สูตร 2^(จำนวนบิต host) − 2 ใช้กับ subnet IPv4 แบบทั่วไป แต่มีข้อยกเว้น เช่น /31 สำหรับลิงก์ point-to-point และ /32 สำหรับที่อยู่เดียว อย่านำสูตรนี้ไปหักสองกับ IPv6

ช่วง IPv4 ที่ควรรู้ความหมาย
10.0.0.0/8Private
172.16.0.0/12Private ตั้งแต่ 172.16.0.0 ถึง 172.31.255.255
192.168.0.0/16Private
127.0.0.0/8Loopback ตัวอย่าง 127.0.0.1
169.254.0.0/16Link-local มักพบเมื่อเครื่องตั้งค่าเองโดยไม่ได้รับ DHCP

Private IP ใช้ภายในและไม่ถูก route บนอินเทอร์เน็ตสาธารณะโดยตรง บ้านทั่วไปใช้ NAT/PAT ที่เราเตอร์เพื่อให้หลายเครื่องออกอินเทอร์เน็ตด้วย IPv4 สาธารณะร่วมกัน NAT ไม่ใช่สิ่งเดียวกับ firewall

อ่านและย่อ IPv6

ตัวอย่างเต็ม: 2001:0db8:0000:0000:0000:0000:0000:0010

  1. ตัดศูนย์นำหน้าในแต่ละกลุ่มได้ เช่น 0db8 เป็น db8 และ 0010 เป็น 10
  2. ย่อกลุ่มที่เป็นศูนย์ทั้งหมดและอยู่ติดกันด้วย :: ได้เพียงครั้งเดียวต่อที่อยู่
  3. จึงเขียนเป็น 2001:db8::10 ได้ เมื่อขยายต้องครบ 8 กลุ่ม

ห้ามตัดศูนย์ท้ายกลุ่ม เช่น 1200 ไม่ใช่ 12 และห้ามใช้ :: สองครั้ง เพราะจะไม่รู้ว่าแต่ละตำแหน่งแทนศูนย์กี่กลุ่ม

IPv6 ที่ควรรู้ความหมาย
::1Loopback
::Unspecified address
fe80::/10Link-local ใช้บนลิงก์เดียว เราเตอร์ไม่ส่งต่อข้ามลิงก์
fc00::/7Unique Local Address หรือ ULA
ff00::/8Multicast
2001:db8::/32สงวนสำหรับตัวอย่างในเอกสาร

IPv6 LAN มักใช้ /64 โดยเฉพาะ SLAAC แต่ไม่ใช่ว่าทุกเครือข่าย IPv6 ต้องใช้ /64 เท่านั้น Dual stack คือใช้งาน IPv4 และ IPv6 ควบคู่กัน ทั้งสองเวอร์ชันไม่ได้สื่อสารกันโดยตรงโดยปราศจากกลไกช่วย เช่น translation

รายละเอียดเพิ่ม: IPv6 มี base header 40 ไบต์ และใช้ extension headers สำหรับข้อมูลเพิ่มเติม เราเตอร์ระหว่างทางไม่ทำ IPv6 fragmentation หากจำเป็นผู้ส่งเป็นฝ่ายแบ่ง โดยทั่วไปอาศัย Path MTU Discovery เพื่อปรับขนาดข้อมูล อ้างอิง RFC 8200

2 Multicast และรูปแบบการส่งข้อมูล

รูปแบบผู้รับตัวอย่างแนวคิด
Unicastปลายทางหนึ่งรายเครื่องลูกข่ายติดต่อเว็บเซิร์ฟเวอร์
Broadcastทุกเครื่องใน broadcast domainARP request ใน IPv4 Ethernet ทั่วไป
Multicastสมาชิกของกลุ่มที่ระบุแจกสตรีมให้กลุ่มผู้รับในเครือข่ายที่รองรับ
Anycastหนึ่งปลายทางจากหลายจุดที่ใช้ที่อยู่เดียวกันเลือกจุดบริการตาม routing metric

Multicast ส่งถึง group address อุปกรณ์เครือข่ายที่รองรับจะทำสำเนาตามเส้นทางไปหาสมาชิก ช่วยลดการส่งข้อมูลซ้ำจากผู้ส่งเมื่อเทียบกับการสร้าง unicast แยกให้ทุกคน ไม่ใช่ส่งให้ทุกเครื่อง และไม่ได้รับประกันว่าทุกคนจะได้รับข้อมูล

  • IPv4 multicast ใช้ช่วง 224.0.0.0/4 หรือ 224.0.0.0–239.255.255.255
  • IPv6 multicast ใช้ ff00::/8
  • IGMP ใช้จัดการสมาชิก multicast สำหรับ IPv4 ส่วน IPv6 ใช้ MLD ซึ่งทำงานผ่าน ICMPv6
  • การข้ามเราเตอร์ต้องมีการรองรับและกำหนดค่า multicast routing ตามเหมาะสม ไม่ได้ใช้ได้ทั่วอินเทอร์เน็ตโดยอัตโนมัติ
  • Anycast คำว่า “ใกล้” หมายถึงตามการเลือกเส้นทาง ไม่จำเป็นต้องใกล้ทางภูมิศาสตร์ที่สุด

ตัวอย่าง: มีผู้ชม 100 คน ถ้าส่ง unicast แยก ผู้ส่งอาจต้องส่ง 100 สตรีม แต่ multicast สามารถส่งเข้าสู่ต้นไม้การกระจายข้อมูลร่วมกัน แล้วคัดลอกเมื่อเส้นทางแยกไปยังกลุ่มผู้รับ ทั้งนี้ต้องมีโครงสร้างพื้นฐานรองรับ

จุดออกสอบ: IPv6 ไม่มี broadcast แต่ยังมี unicast, multicast และ anycast

3 Hexadecimal เลขฐานสิบหก

Hexadecimal หรือ hex ใช้สัญลักษณ์ 16 ตัว คือ 0–9 และ A–F ตัวพิมพ์ใหญ่กับเล็กมีค่าเท่ากัน A=10, B=11, C=12, D=13, E=14 และ F=15

ฐานสิบHexฐานสองฐานสิบHexฐานสอง
000000881000
110001991001
22001010A1010
33001111B1011
44010012C1100
55010113D1101
66011014E1110
77011115F1111

Hex 1 หลักแทน 4 บิต ดังนั้น 2 หลักแทน 1 ไบต์ และ 4 หลักแทน 16 บิต ตัวเขียน 0x เป็นคำนำหน้าที่บอกว่าเป็นฐานสิบหก ไม่ใช่ส่วนหนึ่งของค่าตัวเลข

แปลง Hex เป็นฐานสิบ

ใช้ค่าน้ำหนัก 16^0, 16^1, 16^2 ... จากขวาไปซ้าย

  • 2F = (2 × 16) + 15 = 47
  • FF = (15 × 16) + 15 = 255
  • 1A3 = (1 × 256) + (10 × 16) + 3 = 419

แปลงฐานสิบเป็น Hex

หารด้วย 16 ซ้ำและอ่านเศษย้อนจากท้ายมาหน้า ตัวอย่าง 254 ÷ 16 ได้ 15 เศษ 14 จึงเป็น FE เพราะ 15=F และ 14=E

แปลงฐานสองเป็น Hex

แบ่งบิตจากขวาทีละ 4 บิต ถ้ากลุ่มซ้ายสุดไม่ครบให้เติมศูนย์ด้านหน้า เช่น 11000000 แบ่งเป็น 1100 0000 จึงได้ C0 ซึ่งมีค่า 192 ฐานสิบ

เกี่ยวกับ Network: IPv6 หนึ่งกลุ่มมี hex ได้ 4 หลัก เท่ากับ 16 บิต รวม 8 กลุ่มเป็น 128 บิต ส่วน MAC address แบบ 48 บิตมักเขียน hex 6 คู่ เช่น 02:1A:2B:3C:4D:5E การเขียนด้วย hex ไม่ได้แปลว่าสิ่งนั้นเป็น IPv6 เสมอไป

4 DNS ทำงานหลังบ้านอย่างไร

DNS หรือ Domain Name System เป็นระบบชื่อแบบกระจายลำดับชั้น ใช้ค้นระเบียนของชื่อ เช่น แปลงชื่อเว็บเป็น IPv4 หรือ IPv6 DNS ไม่ได้มีหน้าที่ดาวน์โหลดหน้าเว็บ และชื่อหนึ่งอาจมีหลายที่อยู่ได้

ลำดับเมื่อเปิด https://www.example.com

  1. เบราว์เซอร์และระบบปฏิบัติการอาจตรวจ cache หรือแหล่งชื่อในเครื่องตามการตั้งค่า
  2. หากยังไม่มีคำตอบ เครื่องส่งคำถามผ่าน stub resolver ไปยัง recursive resolver ที่กำหนดไว้ เช่น ขององค์กรหรือ ISP เบราว์เซอร์บางตัวอาจใช้ resolver ผ่าน DoH เอง
  3. หาก recursive resolver มีคำตอบใน cache ที่ยังใช้ได้ ก็ส่งกลับได้ทันที
  4. ถ้าไม่มีข้อมูลที่จำเป็น resolver เริ่มถาม root server ซึ่งชี้ไปยังเซิร์ฟเวอร์ของ .com
  5. เซิร์ฟเวอร์ .com หรือ TLD ชี้ไปยัง authoritative name server ของ example.com
  6. Authoritative server ตอบระเบียนของ www.example.com หากเป็นชื่อแฝง CNAME อาจต้องตามหาชื่อปลายทางต่อ
  7. Resolver เก็บคำตอบตาม TTL และส่งกลับให้เครื่องลูกข่าย
  8. เบราว์เซอร์ใช้ที่อยู่ที่ได้เพื่อเชื่อมต่อปลายทาง แล้วจึงดำเนินขั้นตอน TLS และ HTTP ตามโปรโตคอลที่ใช้

ลำดับ root → TLD → authoritative เป็นกรณีอธิบายเมื่อ cache ไม่ช่วย ในการใช้งานจริงอาจข้ามหลายขั้นเพราะมีข้อมูลเก็บไว้แล้ว แนวคิดระบบชื่อและ resolver ใน RFC 1034

ใครทำหน้าที่อะไร

องค์ประกอบหน้าที่
Stub resolverฝั่งลูกข่าย ส่งคำถามให้ resolver ช่วยค้น
Recursive resolverค้นคำตอบแทนลูกข่ายและใช้ cache
Root serverชี้ทางไปยัง TLD ที่เกี่ยวข้อง
TLD serverให้ข้อมูล delegation ของโดเมนใต้ TLD เช่น .com
Authoritative serverตอบข้อมูลที่ตนมีอำนาจดูแลใน zone

Recursive query คือขอให้ฝั่งที่รับคำถามจัดหาคำตอบหรือแจ้งข้อผิดพลาด ส่วน iterative query อาจได้คำตอบหรือ referral ไปถามเซิร์ฟเวอร์อื่นต่อ

ระเบียนและคำสำคัญ

ชนิดใช้ทำอะไร

AAAAชื่อ → IPv6
CNAMEชื่อแฝง → ชื่อจริงอีกชื่อ

TTL คือระยะเวลาที่อนุญาตให้ cache ระเบียนได้ ไม่ใช่เวลาที่แพ็กเก็ต DNS ใช้เดินทาง การเปลี่ยน DNS อาจไม่ปรากฏพร้อมกันเพราะแต่ละ cache เหลือ TTL ไม่เท่ากัน DNS แบบดั้งเดิมใช้ทั้ง UDP และ TCP พอร์ต 53 ไม่ใช่ UDP อย่างเดียว

DNSSEC ช่วยตรวจสอบความแท้จริงและความครบถ้วนของข้อมูล DNS ด้วยลายเซ็น แต่ไม่เข้ารหัสคำถาม ส่วน DoH และ DoT เข้ารหัสการสื่อสาร DNS ในช่วงที่ใช้งาน ไม่ได้ทำหน้าที่แทน DNSSEC

วิเคราะห์อาการ: ถ้าเปิดด้วยชื่อไม่ได้แต่ระบบเครือข่ายยังติดต่อปลายทางอื่นได้ อาจเกี่ยวกับ DNS แต่การเปิดเว็บ HTTPS ด้วย IP โดยตรงไม่ใช่การทดสอบทดแทนที่สมบูรณ์ เพราะ certificate และ virtual hosting อาจต้องใช้ชื่อโดเมน

5 Network topology

Topology คือรูปแบบการเชื่อมโยงอุปกรณ์ Physical topology คือการต่อจริง ส่วน logical topology คือรูปแบบการไหลของข้อมูล สองอย่างนี้ไม่จำเป็นต้องเหมือนกัน

แบบโครงสร้างข้อดีข้อจำกัดและจุดเสีย
Meshอุปกรณ์เชื่อมถึงกันหลายเส้นทางมีเส้นทางสำรอง ทนต่อบางลิงก์ขัดข้องใช้ลิงก์และพอร์ตมาก บริหารซับซ้อน
Starทุกเครื่องต่อเข้าจุดศูนย์กลางเพิ่มเครื่องและแยกปัญหาง่ายศูนย์กลางเสียอาจกระทบทุกเครื่องที่พึ่งพา
Busใช้สายแกนกลางร่วมกันโครงสร้างง่ายในระบบขนาดเล็กแบบเก่าสายหลักเสียกระทบทั้ง segment และเกิด collision ใน shared Ethernet
Ringเชื่อมเรียงเป็นวงบางระบบควบคุมสิทธิ์ส่งได้เป็นระเบียบวงแบบพื้นฐานขาดอาจหยุดทั้งวง ต้องมีกลไกสำรอง

Mesh

Full mesh คือทุกโหนดมีลิงก์ตรงถึงทุกโหนดอื่น ถ้ามี n โหนด จำนวนลิงก์แบบสองทิศทางหนึ่งลิงก์ต่อคู่คือ n(n−1)/2 เช่น 5 โหนดต้องใช้ 10 ลิงก์ และแต่ละโหนดต้องเชื่อม 4 โหนด Partial mesh เชื่อมเฉพาะบางคู่เพื่อลดต้นทุน ไม่ใช่ mesh ทุกแบบที่ใช้สูตร full mesh ได้

Star

พบได้บ่อยใน Ethernet LAN ที่ใช้ switch เครื่องหนึ่งหรือสายหนึ่งเสียมักกระทบเครื่องนั้น แต่ถ้า switch กลางเสียอาจกระทบทุกเครื่องที่ต่อกับมัน ระบบจริงอาจมีศูนย์กลางและเส้นทางสำรอง

Bus

Ethernet แบบ coaxial รุ่นเก่าใช้สายร่วมและต้องมี terminator ที่ปลายสาย การต่อปลายไม่ถูกต้องอาจทำให้สัญญาณสะท้อน เครือข่ายแบบนี้ต่างจาก Ethernet ที่ใช้ switch แบบ full duplex ในปัจจุบัน

Ring

แต่ละโหนดเชื่อมกับเพื่อนบ้านในวง ระบบ Token Ring ใช้ token ควบคุมสิทธิ์ส่ง แต่ไม่ได้หมายความว่าทุกเทคโนโลยีที่มี topology เป็นวงต้องใช้ token หรือส่งได้ทิศเดียวเสมอ ระบบ dual ring หรือ protection สามารถเพิ่มความทนทานได้

จุดออกสอบ: เครือข่ายที่ใช้ hub อาจเป็น physical star แต่มีลักษณะ shared medium ทางตรรกะ การมีรูปวาดเป็นดาวไม่ได้ยืนยันว่าจะไม่มี collision ต้องดูอุปกรณ์และโหมดการสื่อสารด้วย

6 HTTP และ HTTPS

HTTP คือโปรโตคอลระดับ Application สำหรับ request และ response เช่น ขอหน้าเว็บหรือส่งข้อมูลให้ API ส่วน HTTPS คือการใช้ HTTP ผ่านการเชื่อมต่อที่ได้รับการป้องกันด้วย TLS

ประเด็นHTTP ที่ไม่ใช้ TLSHTTPS
URL schemehttp://https://
พอร์ตปริยาย80443
การรักษาความลับไม่มีจาก HTTP เองTLS เข้ารหัสข้อมูลระหว่างปลายทาง TLS
ตรวจการแก้ไขระหว่างทางไม่มีการคุ้มครองแบบ TLSTLS ช่วยตรวจจับการแก้ไข
ยืนยันตัวตนเซิร์ฟเวอร์ไม่มีด้วย TLS certificateใช้ certificate และการตรวจสอบชื่อ/สายความเชื่อถือ

พอร์ตเป็นค่าปริยาย สามารถกำหนดพอร์ตอื่นได้ HTTPS ช่วยคุ้มครองการสื่อสาร แต่ไม่ได้รับประกันว่าเจ้าของเว็บน่าเชื่อถือหรือเนื้อหาปลอดภัย HTTP และ HTTPS ใน RFC 9110

กระบวนการแบบเข้าใจง่าย

หลัง DNS ให้ IP แล้ว สำหรับ HTTP/1.1 หรือ HTTP/2 ผ่าน HTTPS โดยทั่วไปเครื่องตั้ง TCP connection แล้วทำ TLS handshake ตรวจ certificate ตกลงกุญแจ และแลกเปลี่ยน HTTP ภายในช่องทางที่เข้ารหัส รายละเอียดอาจต่างเมื่อใช้ connection เดิมหรือ session resumption ส่วน HTTP/3 ใช้ QUIC บน UDP และผสาน TLS 1.3 จึงไม่ควรจำว่า HTTPS ต้องใช้ TCP เสมอ

TLS คุ้มครองเนื้อหา HTTP เช่น path, query, headers และ body ระหว่างปลายทาง TLS แต่ผู้สังเกตเครือข่ายยังอาจเห็น IP ขนาด/เวลาแพ็กเก็ต และข้อมูลชื่อจาก DNS หรือขั้นตอนเชื่อมต่อ ขึ้นกับการตั้งค่าความเป็นส่วนตัว

คำที่ควรจำ

  • GET: ขอข้อมูล ส่วน POST: ส่งข้อมูลเพื่อให้ปลายทางประมวลผลตามความหมายของระบบ
  • 200: สำเร็จ, 301/302: เปลี่ยนเส้นทาง, 404: ไม่พบทรัพยากร, 500: เซิร์ฟเวอร์เกิดข้อผิดพลาด
  • HTTP เป็น stateless ในระดับโปรโตคอล แอปพลิเคชันใช้ cookie หรือ token เชื่อมคำขอเข้ากับสถานะผู้ใช้ได้
  • HTTP และ HTTPS อยู่ระดับ Application เหมือนกัน HTTPS ไม่ใช่ OSI ชั้นที่ 8

7 OSI Model แบบละเอียด

OSI เป็นแบบจำลองอ้างอิง 7 ชั้น ช่วยแบ่งหน้าที่และวิเคราะห์ปัญหา ระบบอินเทอร์เน็ตจริงใช้ชุด TCP/IP ซึ่งไม่ได้แยกทั้ง 7 ชั้นเป็นโมดูลตรงตัวเสมอไป โดยเฉพาะ Session และ Presentation มักรวมอยู่ในโปรแกรมหรือไลบรารี

ตารางภาพรวมจากบนลงล่าง

ชั้นชื่อหน้าที่หลักหน่วยข้อมูลที่มักใช้สอนตัวอย่าง
7Applicationบริการเครือข่ายที่แอปเรียกใช้DataHTTP, DNS, SMTP
6Presentationรูปแบบข้อมูล การเข้ารหัส การบีบอัดDataEncoding และ serialization
5SessionจัดการบทสนทนาและจุดประสานงานDataการเปิด คงไว้ และยุติบทสนทนา
4Transportส่งระหว่าง process และแยกบริการด้วย portTCP segment / UDP datagramTCP, UDP
3Networkที่อยู่เชิงตรรกะและ routing ข้ามเครือข่ายPacketIPv4, IPv6, router
2Data Linkส่ง frame ภายในลิงก์และใช้ MACFrameEthernet, Wi-Fi MAC, switch

คำว่า PDU คือ Protocol Data Unit ชื่อหน่วยข้อมูลที่ใช้ในแต่ละโปรโตคอล คำเรียกในตารางเป็นรูปแบบที่นิยมใช้เรียน ไม่ใช่ชื่อเดียวที่ใช้ได้ทุกบริบท

Layer 7 Application

ให้บริการเครือข่ายแก่แอป เช่น HTTP สำหรับเว็บ DNS สำหรับค้นระเบียนชื่อ และ SMTP สำหรับส่งอีเมล “Application layer” ไม่ได้หมายถึงหน้าจอโปรแกรมทั้งหมด แต่หมายถึงหน้าที่สื่อสารระดับแอป

ตัวอย่างอาการ: เว็บตอบ 404 แปลว่าได้รับ HTTP response แล้ว จึงไม่ควรสรุปทันทีว่าสายเครือข่ายขาด สาเหตุอาจเป็น path หรือการตั้งค่าเว็บ

Layer 6 Presentation

ดูแลให้ปลายทางตีความข้อมูลตรงกัน เช่น รูปแบบอักขระ UTF-8 การแปลงโครงสร้างข้อมูล และการบีบอัด แนวคิดเรื่อง encryption มักอธิบายร่วมกับชั้นนี้ในตำรา แต่ TLS ในระบบ TCP/IP จริงไม่ควรถูกจัดว่าต้องอยู่ Layer 6 อย่างตายตัว

ตัวอย่างอาการ: ข้อความแสดงเป็นตัวอักษรผิด หรือโปรแกรมอ่านรูปแบบข้อมูลไม่ได้ อาจเกี่ยวกับ encoding หรือรูปแบบที่ตกลงกัน

Layer 5 Session

จัดการการเริ่ม คงไว้ และจบการสนทนาระหว่างระบบ รวมถึงการประสานลำดับและจุดกลับมาทำงานต่อในระบบที่รองรับ แนวคิด session ในเว็บ เช่น login session มักถูกจัดการในระดับแอป ไม่ได้พิสูจน์ว่ามีโปรโตคอล Layer 5 แยกอยู่

ตัวอย่าง: ระบบประชุมหรือบริการแบบมีบทสนทนาอาจต้องรักษาบริบทของคู่สื่อสาร แต่ต้องวิเคราะห์โปรโตคอลจริงก่อนจับคู่กับ OSI

Layer 4 Transport

ใช้ port เพื่อแยก process หรือบริการบนเครื่องเดียวกัน เช่น client ใช้ source port ชั่วคราวติดต่อ destination port 443

TCPUDP
สร้าง connection และส่งเป็น byte streamส่งเป็น datagram
มี sequence, acknowledgement และ retransmissionไม่มีการรับประกันส่งถึงหรือเรียงลำดับใน UDP เอง
มี flow control และ congestion controlแอปต้องจัดการสิ่งที่ต้องการเพิ่มเอง
เหมาะเมื่ออยากได้ข้อมูลครบและตามลำดับเหมาะกับงานที่ออกแบบการส่งตามความต้องการของแอป

TCP ไม่รับประกันว่าแอปปลายทางประมวลผลสำเร็จ และ UDP ไม่ได้ “เร็วกว่าเสมอ” QUIC สามารถให้ reliable streams บน UDP ได้ เป็นตัวอย่างว่าต้องแยกคุณสมบัติ UDP ออกจากโปรโตคอลที่สร้างทับมัน

Layer 3 Network

ใช้ IP address และ routing table เพื่อเลือก next hop ถ้าปลายทางอยู่นอก subnet เครื่องมักส่งให้ default gateway เราเตอร์อ่าน IP ปลายทางแล้วส่งต่อไปยังเส้นทางที่เหมาะสม TTL ของ IPv4 หรือ Hop Limit ของ IPv6 ลดลงตามการส่งต่อ ช่วยจำกัดแพ็กเก็ตวนลูป

ตัวอย่างปัญหา: subnet mask ผิด ไม่มี default gateway หรือไม่มี route ไปปลายทาง Router อยู่ชั้น 3 เป็นหลัก แต่เครื่องจริงอาจทำ firewall หรือหน้าที่ชั้นอื่นร่วมด้วย

Layer 2 Data Link

บรรจุข้อมูลเป็น frame สำหรับส่งในลิงก์ ใช้ MAC address ใน Ethernet และมี FCS ช่วยตรวจข้อผิดพลาด Switch เรียนรู้ source MAC ที่แต่ละพอร์ต แล้วใช้ destination MAC เลือกพอร์ตส่งออก หากเป็น unknown unicast อาจ flood ภายใน VLAN

VLAN แบ่งเครือข่าย Layer 2 เป็นคนละ broadcast domain การอยู่ในอาคารเดียวกันจึงไม่ได้หมายความว่าอยู่ใน subnet หรือ VLAN เดียวกันเสมอไป Switch Layer 3 สามารถ route ได้ด้วย

Layer 1 Physical

เกี่ยวกับสัญญาณไฟฟ้า แสง คลื่นวิทยุ สาย หัวต่อ ระยะทาง และอัตราส่งข้อมูล ตัวอย่างอุปกรณ์เชิงชั้นคือ repeater และ hub ปัญหาที่พบบ่อย ได้แก่ สายหลวม ไม่มี link หรือสัญญาณรบกวน

Encapsulation และ Decapsulation

ฝั่งส่ง: ข้อมูลแอป → TCP segment หรือ UDP datagram → IP packet → frame → สัญญาณ

ฝั่งรับ: สัญญาณ → frame → IP packet → transport data → ข้อมูลแอป

แต่ละชั้นเติมข้อมูลควบคุม เช่น header และบางชั้นมี trailer ฝั่งรับอ่านและถอดตามลำดับ เราเตอร์ระหว่างทางถอด frame ขาเข้า ประมวลผล IP และสร้าง frame สำหรับลิงก์ขาออก ไม่ต้องเปิดอ่านข้อมูลแอปทุกครั้งเพื่อ route

ตัวอย่างส่งไปเว็บต่างเครือข่าย

สมมติ PC เป็น 192.168.1.10/24, gateway เป็น 192.168.1.1 และเว็บตัวอย่างเป็น 203.0.113.20

  1. PC เห็นว่า IP เว็บอยู่นอก subnet จึงเลือก gateway เป็น next hop
  2. PC ใช้ ARP หา MAC ของ gateway หากยังไม่มีใน cache
  3. IP packet มี destination IP เป็นเว็บ แต่ Ethernet frame มี destination MAC เป็น gateway
  4. เราเตอร์ส่งต่อและเปลี่ยน Layer 2 header ให้เหมาะกับลิงก์ถัดไป
  5. IP ปลายทางมักคงเดิมตลอดเส้นทาง แต่ NAT และกลไกบางประเภทอาจแก้ที่อยู่หรือ port

203.0.113.20 เป็นที่อยู่สำหรับเอกสารตัวอย่าง ไม่ใช่เว็บจริงให้ทดลอง

จำให้แม่น: MAC ช่วยส่งภายในลิงก์, IP ช่วยส่งข้ามเครือข่าย, port ช่วยเลือกบริการหรือ process

บางหลักสูตรใช้ TCP/IP แบบ 5 ชั้นโดยแยก Physical ออก ควรดูรูปแบบที่อาจารย์ใช้ประกอบ

วิธีไล่ปัญหาสำหรับข้อสอบสถานการณ์

  1. Physical: มีไฟ link หรือเชื่อมต่อ Wi-Fi ได้หรือไม่
  2. Data Link: พอร์ตและ VLAN ถูกหรือไม่ เชื่อมถึงเพื่อนบ้านบนลิงก์ได้หรือไม่
  3. Network: IP, prefix, gateway และ route ถูกหรือไม่
  4. Transport: ติดต่อ port ที่ต้องการได้หรือไม่ มี firewall ปิดกั้นหรือไม่
  5. ชั้นบน: DNS ตอบหรือไม่ TLS certificate ถูกหรือไม่ แอปตอบอะไรกลับมา

Ping ใช้ ICMP ไม่ใช่ TCP หรือ UDP และ ping ไม่ผ่านไม่ได้แปลว่าเครื่องดับเสมอ เพราะอาจถูกกรอง ส่วน ping ผ่านก็ไม่ได้ยืนยันว่าเว็บหรือ port 443 ใช้งานได้

ตัวอย่างบ้านเชื่อมบริษัท

อุปกรณ์ในบ้าน → switch หรือ access point → router → เครือข่าย ISP และอินเทอร์เน็ต → router บริษัท → LAN บริษัท

  • พอร์ต LAN บนเราเตอร์บ้านมักต่ออุปกรณ์ภายใน ส่วน WAN เป็นฝั่ง uplink ไปเครือข่ายผู้ให้บริการ
  • Wi-Fi คือเทคโนโลยีเชื่อมต่อแบบไร้สาย ไม่ใช่อินเทอร์เน็ต ต่อ Wi-Fi ได้แต่ไม่มีอินเทอร์เน็ตก็เป็นไปได้
  • LAN ทำงานภายในได้แม้ไม่มีอินเทอร์เน็ต เช่น แชร์ไฟล์หรือพิมพ์งานกับเครื่องพิมพ์ในวงเดียวกัน
  • Router บ้านหนึ่งเครื่องมักรวมหลายหน้าที่ เช่น router, switch, access point, DHCP server และ NAT
  • Public/private IP ไม่ใช่คำเดียวกับ WAN/LAN ฝั่ง WAN อาจได้ private address หรือที่อยู่หลัง CGNAT จากผู้ให้บริการ

แบบฝึกหัด

  1. IPv6 มีความยาวเท่าไร และ hex หนึ่งหลักแทนกี่บิต
  2. ย่อ 2001:0db8:0000:0000:0000:0000:0000:0001
  3. แปลง 3A ฐานสิบหกเป็นฐานสิบ
  4. แปลง 192 ฐานสิบเป็น hex
  5. Full mesh จำนวน 6 โหนดต้องใช้กี่ลิงก์
  6. ส่งข้อมูลให้เฉพาะสมาชิกกลุ่มเรียกการส่งแบบใด
  7. DNS record ที่คืน IPv6 คืออะไร
  8. Root DNS server เก็บ IP ของทุกเว็บหรือไม่
  9. ทำไมแก้ DNS แล้วผู้ใช้บางคนยังเห็นคำตอบเก่า
  10. Switch ทั่วไปกับ router ทำงานหลักที่ OSI ชั้นใด
  11. ส่งไปนอก subnet ต้องใส่ MAC ของเว็บปลายทางใน frame แรกหรือไม่
  12. HTTPS รับประกันว่าเว็บไม่หลอกลวงหรือไม่
  13. UDP มีการส่งซ้ำให้อัตโนมัติในตัวโปรโตคอลหรือไม่
  14. LAN จำเป็นต้องมีอินเทอร์เน็ตหรือไม่
  15. เครื่อง 192.168.1.10/24 กับ 192.168.2.10/24 อยู่ subnet เดียวกันหรือไม่
  16. Ping ผ่านแล้วรับประกันหรือไม่ว่า HTTP ใช้งานได้
  17. IPv6 มี broadcast หรือไม่
  18. TCP/IP แบบ 4 ชั้นรวม OSI ชั้นใดเป็น Application

เฉลยพร้อมเหตุผล

  1. 128 บิต และ 4 บิตต่อ hex หนึ่งหลัก
  2. 2001:db8::1 โดย :: แทนศูนย์ 6 กลุ่ม
  3. 58 เพราะ (3 × 16) + 10
  4. C0 เพราะ 12 × 16 = 192
  5. 15 ลิงก์ เพราะ 6 × 5 ÷ 2
  6. Multicast
  7. AAAA
  8. ไม่เก็บทั้งหมด หน้าที่สำคัญคือให้ referral ไปยัง TLD ที่เกี่ยวข้อง
  9. Cache เก่าอาจยังไม่หมด TTL
  10. Switch Layer 2 และ router Layer 3 โดยอุปกรณ์จริงอาจทำหลายชั้น
  11. ไม่ใช่ ใช้ MAC ของ next hop เช่น default gateway ส่วน destination IP เป็นเว็บ
  12. ไม่รับประกัน TLS ช่วยคุ้มครองการสื่อสารและตรวจตัวตนตาม certificate
  13. ไม่มีใน UDP เอง แอปหรือโปรโตคอลที่ทำงานบน UDP อาจเพิ่มได้
  14. ไม่จำเป็น LAN ยังให้บริการภายในได้
  15. ไม่อยู่ subnet เดียวกันภายใต้ /24 ต้องอาศัย routing เพื่อสื่อสารข้าม subnet
  16. ไม่รับประกัน ICMP ผ่านไม่ได้ยืนยันว่าเว็บหรือ port ที่ต้องการเปิดอยู่
  17. ไม่มี ใช้ multicast สำหรับหลายหน้าที่ที่เคยอาศัย broadcast
  18. ชั้น 5, 6 และ 7
