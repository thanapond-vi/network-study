1 IPv4 และ IPv6

IP ย่อมาจาก Internet Protocol ทำหน้าที่ระบุที่อยู่และส่งแพ็กเก็ตข้ามเครือข่าย อยู่ในชั้น Network ของ OSI ที่อยู่ IP โดยหลักผูกกับอินเทอร์เฟซของอุปกรณ์ อุปกรณ์หนึ่งจึงมีหลาย IP ได้ IP เป็นบริการแบบ best effort ไม่รับประกันว่าข้อมูลจะถึง ครบ หรือตามลำดับ

รูปแบบเลขฐานสิบ 4 ชุด คั่นด้วยจุดเลขฐานสิบหก 8 กลุ่ม คั่นด้วย colon

จำนวนที่อยู่ข้างต้นเป็นจำนวนทั้งหมดทางคณิตศาสตร์ ไม่ใช่จำนวนที่นำไปแจกเป็น public address ได้ทั้งหมด IPv6 ไม่ได้เร็วกว่า IPv4 หรือปลอดภัยกว่าโดยอัตโนมัติ ผลจริงขึ้นกับเส้นทาง อุปกรณ์ และการตั้งค่า

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "The main difference is address size — IPv4 is 32 bits and IPv6 is 128 bits. IPv6 also drops broadcast, uses Neighbor Discovery instead of ARP, and supports SLAAC, so hosts can configure their own addresses."แปล: "ความต่างหลักคือขนาดที่อยู่ IPv4 ยาว 32 บิต ส่วน IPv6 ยาว 128 บิต IPv6 ยังไม่มี broadcast ใช้ Neighbor Discovery แทน ARP และรองรับ SLAAC ทำให้ host ตั้งที่อยู่เองได้"

อ่าน IPv4 และ prefix

192.168.1.10/24 หมายถึงส่วนเครือข่ายยาว 24 บิต เหลือส่วน host 8 บิต Subnet mask คือ 255.255.255.0 สำหรับ subnet นี้ network address คือ 192.168.1.0 และ broadcast address คือ 192.168.1.255 ที่อยู่ host แบบทั่วไปใช้ได้ .1 ถึง .254 รวม 254 ที่อยู่

สูตร 2^(จำนวนบิต host) − 2 ใช้กับ subnet IPv4 แบบทั่วไป แต่มีข้อยกเว้น เช่น /31 สำหรับลิงก์ point-to-point และ /32 สำหรับที่อยู่เดียว อย่านำสูตรนี้ไปหักสองกับ IPv6

อ่านและย่อ IPv6

ตัวอย่างเต็ม: 2001:0db8:0000:0000:0000:0000:0000:0010

  1. ตัดศูนย์นำหน้าในแต่ละกลุ่มได้ เช่น 0db8 เป็น db8 และ 0010 เป็น 10
  2. ย่อกลุ่มที่เป็นศูนย์ทั้งหมดและอยู่ติดกันด้วย :: ได้เพียงครั้งเดียวต่อที่อยู่
  3. จึงเขียนเป็น 2001:db8::10 ได้ เมื่อขยายต้องครบ 8 กลุ่ม

ห้ามตัดศูนย์ท้ายกลุ่ม เช่น 1200 ไม่ใช่ 12 และห้ามใช้ :: สองครั้ง เพราะจะไม่รู้ว่าแต่ละตำแหน่งแทนศูนย์กี่กลุ่ม

รายละเอียดเพิ่ม: IPv6 มี base header 40 ไบต์ และใช้ extension headers สำหรับข้อมูลเพิ่มเติม เราเตอร์ระหว่างทางไม่ทำ IPv6 fragmentation หากจำเป็นผู้ส่งเป็นฝ่ายแบ่ง โดยทั่วไปอาศัย Path MTU Discovery เพื่อปรับขนาดข้อมูล อ้างอิง RFC 8200

2 Multicast และรูปแบบการส่งข้อมูล

รูปแบบผู้รับตัวอย่างแนวคิด
Unicastปลายทางหนึ่งรายเครื่องลูกข่ายติดต่อเว็บเซิร์ฟเวอร์
Broadcastทุกเครื่องใน broadcast domainARP request ใน IPv4 Ethernet ทั่วไป
Multicastสมาชิกของกลุ่มที่ระบุแจกสตรีมให้กลุ่มผู้รับในเครือข่ายที่รองรับ
Anycastหนึ่งปลายทางจากหลายจุดที่ใช้ที่อยู่เดียวกันเลือกจุดบริการตาม routing metric

Multicast ส่งถึง group address อุปกรณ์เครือข่ายที่รองรับจะทำสำเนาตามเส้นทางไปหาสมาชิก ช่วยลดการส่งข้อมูลซ้ำจากผู้ส่งเมื่อเทียบกับการสร้าง unicast แยกให้ทุกคน ไม่ใช่ส่งให้ทุกเครื่อง และไม่ได้รับประกันว่าทุกคนจะได้รับข้อมูล

  • IPv4 multicast ใช้ช่วง 224.0.0.0/4 หรือ 224.0.0.0–239.255.255.255
  • IPv6 multicast ใช้ ff00::/8
  • IGMP ใช้จัดการสมาชิก multicast สำหรับ IPv4 ส่วน IPv6 ใช้ MLD ซึ่งทำงานผ่าน ICMPv6
  • การข้ามเราเตอร์ต้องมีการรองรับและกำหนดค่า multicast routing ตามเหมาะสม ไม่ได้ใช้ได้ทั่วอินเทอร์เน็ตโดยอัตโนมัติ
  • Anycast คำว่า “ใกล้” หมายถึงตามการเลือกเส้นทาง ไม่จำเป็นต้องใกล้ทางภูมิศาสตร์ที่สุด

ตัวอย่าง: มีผู้ชม 100 คน ถ้าส่ง unicast แยก ผู้ส่งอาจต้องส่ง 100 สตรีม แต่ multicast สามารถส่งเข้าสู่ต้นไม้การกระจายข้อมูลร่วมกัน แล้วคัดลอกเมื่อเส้นทางแยกไปยังกลุ่มผู้รับ ทั้งนี้ต้องมีโครงสร้างพื้นฐานรองรับ

จุดออกสอบ: IPv6 ไม่มี broadcast แต่ยังมี unicast, multicast และ anycast

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "Unicast is one-to-one, broadcast is one-to-all on the local segment, multicast is one-to-many for subscribed members, and anycast is one-to-nearest by routing. IPv6 has no broadcast."แปล: "Unicast คือหนึ่งต่อหนึ่ง broadcast คือหนึ่งต่อทุกเครื่องใน segment multicast คือหนึ่งต่อสมาชิกกลุ่มที่สมัครไว้ และ anycast คือหนึ่งต่อปลายทางที่ใกล้ที่สุดตาม routing ทั้งนี้ IPv6 ไม่มี broadcast"

3 Hexadecimal เลขฐานสิบหก

Hex 1 หลักแทน 4 บิต ดังนั้น 2 หลักแทน 1 ไบต์ และ 4 หลักแทน 16 บิต ตัวเขียน 0x เป็นคำนำหน้าที่บอกว่าเป็นฐานสิบหก ไม่ใช่ส่วนหนึ่งของค่าตัวเลข

แปลง Hex เป็นฐานสิบ

ใช้ค่าน้ำหนัก 16^0, 16^1, 16^2 ... จากขวาไปซ้าย

  • 2F = (2 × 16) + 15 = 47
  • FF = (15 × 16) + 15 = 255
  • 1A3 = (1 × 256) + (10 × 16) + 3 = 419

แปลงฐานสิบเป็น Hex

หารด้วย 16 ซ้ำและอ่านเศษย้อนจากท้ายมาหน้า ตัวอย่าง 254 ÷ 16 ได้ 15 เศษ 14 จึงเป็น FE เพราะ 15=F และ 14=E

แปลงฐานสองเป็น Hex

แบ่งบิตจากขวาทีละ 4 บิต ถ้ากลุ่มซ้ายสุดไม่ครบให้เติมศูนย์ด้านหน้า เช่น 11000000 แบ่งเป็น 1100 0000 จึงได้ C0 ซึ่งมีค่า 192 ฐานสิบ

เกี่ยวกับ Network: IPv6 หนึ่งกลุ่มมี hex ได้ 4 หลัก เท่ากับ 16 บิต รวม 8 กลุ่มเป็น 128 บิต ส่วน MAC address แบบ 48 บิตมักเขียน hex 6 คู่ เช่น 02:1A:2B:3C:4D:5E การเขียนด้วย hex ไม่ได้แปลว่าสิ่งนั้นเป็น IPv6 เสมอไป

4 DNS ทำงานหลังบ้านอย่างไร

DNS หรือ Domain Name System เป็นระบบชื่อแบบกระจายลำดับชั้น ใช้ค้นระเบียนของชื่อ เช่น แปลงชื่อเว็บเป็น IPv4 หรือ IPv6 DNS ไม่ได้มีหน้าที่ดาวน์โหลดหน้าเว็บ และชื่อหนึ่งอาจมีหลายที่อยู่ได้

ลำดับเมื่อเปิด https://www.example.com

  1. เบราว์เซอร์และระบบปฏิบัติการอาจตรวจ cache หรือแหล่งชื่อในเครื่องตามการตั้งค่า
  2. หากยังไม่มีคำตอบ เครื่องส่งคำถามผ่าน stub resolver ไปยัง recursive resolver ที่กำหนดไว้ เช่น ขององค์กรหรือ ISP เบราว์เซอร์บางตัวอาจใช้ resolver ผ่าน DoH เอง
  3. หาก recursive resolver มีคำตอบใน cache ที่ยังใช้ได้ ก็ส่งกลับได้ทันที
  4. ถ้าไม่มีข้อมูลที่จำเป็น resolver เริ่มถาม root server ซึ่งชี้ไปยังเซิร์ฟเวอร์ของ .com
  5. เซิร์ฟเวอร์ .com หรือ TLD ชี้ไปยัง authoritative name server ของ example.com
  6. Authoritative server ตอบระเบียนของ www.example.com หากเป็นชื่อแฝง CNAME อาจต้องตามหาชื่อปลายทางต่อ
  7. Resolver เก็บคำตอบตาม TTL และส่งกลับให้เครื่องลูกข่าย
  8. เบราว์เซอร์ใช้ที่อยู่ที่ได้เพื่อเชื่อมต่อปลายทาง แล้วจึงดำเนินขั้นตอน TLS และ HTTP ตามโปรโตคอลที่ใช้

ลำดับ root → TLD → authoritative เป็นกรณีอธิบายเมื่อ cache ไม่ช่วย ในการใช้งานจริงอาจข้ามหลายขั้นเพราะมีข้อมูลเก็บไว้แล้ว แนวคิดระบบชื่อและ resolver ใน RFC 1034

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "First the browser checks its local cache. If it misses, the stub resolver asks a recursive resolver. On a cache miss, the resolver walks the hierarchy — root, then the TLD, then the authoritative server — caches the answer for the TTL, and returns the IP address. Then the browser opens the connection and does the TLS handshake."แปล: "อันดับแรกเบราว์เซอร์ตรวจ cache ในเครื่อง ถ้าไม่มี stub resolver จะถาม recursive resolver ถ้า resolver ไม่มีใน cache ก็ไล่ถามตามลำดับชั้น คือ root, TLD แล้ว authoritative server เก็บคำตอบไว้ตาม TTL และส่ง IP กลับมา จากนั้นเบราว์เซอร์จึงเปิดการเชื่อมต่อและทำ TLS handshake"

TTL คือระยะเวลาที่อนุญาตให้ cache ระเบียนได้ ไม่ใช่เวลาที่แพ็กเก็ต DNS ใช้เดินทาง การเปลี่ยน DNS อาจไม่ปรากฏพร้อมกันเพราะแต่ละ cache เหลือ TTL ไม่เท่ากัน DNS แบบดั้งเดิมใช้ทั้ง UDP และ TCP พอร์ต 53 ไม่ใช่ UDP อย่างเดียว

DNSSEC ช่วยตรวจสอบความแท้จริงและความครบถ้วนของข้อมูล DNS ด้วยลายเซ็น แต่ไม่เข้ารหัสคำถาม ส่วน DoH และ DoT เข้ารหัสการสื่อสาร DNS ในช่วงที่ใช้งาน ไม่ได้ทำหน้าที่แทน DNSSEC

วิเคราะห์อาการ: ถ้าเปิดด้วยชื่อไม่ได้แต่ระบบเครือข่ายยังติดต่อปลายทางอื่นได้ อาจเกี่ยวกับ DNS แต่การเปิดเว็บ HTTPS ด้วย IP โดยตรงไม่ใช่การทดสอบทดแทนที่สมบูรณ์ เพราะ certificate และ virtual hosting อาจต้องใช้ชื่อโดเมน

5 Network topology

Topology คือรูปแบบการเชื่อมโยงอุปกรณ์ Physical topology คือการต่อจริง ส่วน logical topology คือรูปแบบการไหลของข้อมูล สองอย่างนี้ไม่จำเป็นต้องเหมือนกัน

แบบโครงสร้างข้อดีข้อจำกัดและจุดเสีย
Meshอุปกรณ์เชื่อมถึงกันหลายเส้นทางมีเส้นทางสำรอง ทนต่อบางลิงก์ขัดข้องใช้ลิงก์และพอร์ตมาก บริหารซับซ้อน
Starทุกเครื่องต่อเข้าจุดศูนย์กลางเพิ่มเครื่องและแยกปัญหาง่ายศูนย์กลางเสียอาจกระทบทุกเครื่องที่พึ่งพา
Busใช้สายแกนกลางร่วมกันโครงสร้างง่ายในระบบขนาดเล็กแบบเก่าสายหลักเสียกระทบทั้ง segment และเกิด collision ใน shared Ethernet
Ringเชื่อมเรียงเป็นวงบางระบบควบคุมสิทธิ์ส่งได้เป็นระเบียบวงแบบพื้นฐานขาดอาจหยุดทั้งวง ต้องมีกลไกสำรอง

Mesh

Full mesh คือทุกโหนดมีลิงก์ตรงถึงทุกโหนดอื่น ถ้ามี n โหนด จำนวนลิงก์แบบสองทิศทางหนึ่งลิงก์ต่อคู่คือ n(n−1)/2 เช่น 5 โหนดต้องใช้ 10 ลิงก์ และแต่ละโหนดต้องเชื่อม 4 โหนด Partial mesh เชื่อมเฉพาะบางคู่เพื่อลดต้นทุน ไม่ใช่ mesh ทุกแบบที่ใช้สูตร full mesh ได้

Star

พบได้บ่อยใน Ethernet LAN ที่ใช้ switch เครื่องหนึ่งหรือสายหนึ่งเสียมักกระทบเครื่องนั้น แต่ถ้า switch กลางเสียอาจกระทบทุกเครื่องที่ต่อกับมัน ระบบจริงอาจมีศูนย์กลางและเส้นทางสำรอง

Bus

Ethernet แบบ coaxial รุ่นเก่าใช้สายร่วมและต้องมี terminator ที่ปลายสาย การต่อปลายไม่ถูกต้องอาจทำให้สัญญาณสะท้อน เครือข่ายแบบนี้ต่างจาก Ethernet ที่ใช้ switch แบบ full duplex ในปัจจุบัน

Ring

แต่ละโหนดเชื่อมกับเพื่อนบ้านในวง ระบบ Token Ring ใช้ token ควบคุมสิทธิ์ส่ง แต่ไม่ได้หมายความว่าทุกเทคโนโลยีที่มี topology เป็นวงต้องใช้ token หรือส่งได้ทิศเดียวเสมอ ระบบ dual ring หรือ protection สามารถเพิ่มความทนทานได้

จุดออกสอบ: เครือข่ายที่ใช้ hub อาจเป็น physical star แต่มีลักษณะ shared medium ทางตรรกะ การมีรูปวาดเป็นดาวไม่ได้ยืนยันว่าจะไม่มี collision ต้องดูอุปกรณ์และโหมดการสื่อสารด้วย

ตรวจการแก้ไขระหว่างทางไม่มีการคุ้มครองแบบ TLSTLS ช่วยตรวจจับการแก้ไข

พอร์ตเป็นค่าปริยาย สามารถกำหนดพอร์ตอื่นได้ HTTPS ช่วยคุ้มครองการสื่อสาร แต่ไม่ได้รับประกันว่าเจ้าของเว็บน่าเชื่อถือหรือเนื้อหาปลอดภัย HTTP และ HTTPS ใน RFC 9110

กระบวนการแบบเข้าใจง่าย

หลัง DNS ให้ IP แล้ว สำหรับ HTTP/1.1 หรือ HTTP/2 ผ่าน HTTPS โดยทั่วไปเครื่องตั้ง TCP connection แล้วทำ TLS handshake ตรวจ certificate ตกลงกุญแจ และแลกเปลี่ยน HTTP ภายในช่องทางที่เข้ารหัส รายละเอียดอาจต่างเมื่อใช้ connection เดิมหรือ session resumption ส่วน HTTP/3 ใช้ QUIC บน UDP และผสาน TLS 1.3 จึงไม่ควรจำว่า HTTPS ต้องใช้ TCP เสมอ

TLS คุ้มครองเนื้อหา HTTP เช่น path, query, headers และ body ระหว่างปลายทาง TLS แต่ผู้สังเกตเครือข่ายยังอาจเห็น IP ขนาด/เวลาแพ็กเก็ต และข้อมูลชื่อจาก DNS หรือขั้นตอนเชื่อมต่อ ขึ้นกับการตั้งค่าความเป็นส่วนตัว

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "HTTPS is just HTTP over TLS. TLS gives you three things: confidentiality through encryption, integrity so tampering is detected, and server authentication through certificates. It doesn't tell you whether the site itself is trustworthy."แปล: "HTTPS คือ HTTP ที่วิ่งบน TLS ซึ่งให้สามอย่าง คือความลับด้วยการเข้ารหัส ความถูกต้องที่ตรวจจับการแก้ไขได้ และการยืนยันตัวตนเซิร์ฟเวอร์ด้วย certificate แต่ไม่ได้บอกว่าเว็บไซต์นั้นน่าเชื่อถือหรือไม่"

คำที่ควรจำ

  • GET: ขอข้อมูล ส่วน POST: ส่งข้อมูลเพื่อให้ปลายทางประมวลผลตามความหมายของระบบ
  • 200: สำเร็จ, 301/302: เปลี่ยนเส้นทาง, 404: ไม่พบทรัพยากร, 500: เซิร์ฟเวอร์เกิดข้อผิดพลาด
  • HTTP เป็น stateless ในระดับโปรโตคอล แอปพลิเคชันใช้ cookie หรือ token เชื่อมคำขอเข้ากับสถานะผู้ใช้ได้
  • HTTP และ HTTPS อยู่ระดับ Application เหมือนกัน HTTPS ไม่ใช่ OSI ชั้นที่ 8

7 OSI Model แบบละเอียด

OSI เป็นแบบจำลองอ้างอิง 7 ชั้น ช่วยแบ่งหน้าที่และวิเคราะห์ปัญหา ระบบอินเทอร์เน็ตจริงใช้ชุด TCP/IP ซึ่งไม่ได้แยกทั้ง 7 ชั้นเป็นโมดูลตรงตัวเสมอไป โดยเฉพาะ Session และ Presentation มักรวมอยู่ในโปรแกรมหรือไลบรารี

Layer 7 Application

ให้บริการเครือข่ายแก่แอป เช่น HTTP สำหรับเว็บ DNS สำหรับค้นระเบียนชื่อ และ SMTP สำหรับส่งอีเมล “Application layer” ไม่ได้หมายถึงหน้าจอโปรแกรมทั้งหมด แต่หมายถึงหน้าที่สื่อสารระดับแอป

ตัวอย่างอาการ: เว็บตอบ 404 แปลว่าได้รับ HTTP response แล้ว จึงไม่ควรสรุปทันทีว่าสายเครือข่ายขาด สาเหตุอาจเป็น path หรือการตั้งค่าเว็บ

Layer 6 Presentation

ดูแลให้ปลายทางตีความข้อมูลตรงกัน เช่น รูปแบบอักขระ UTF-8 การแปลงโครงสร้างข้อมูล และการบีบอัด แนวคิดเรื่อง encryption มักอธิบายร่วมกับชั้นนี้ในตำรา แต่ TLS ในระบบ TCP/IP จริงไม่ควรถูกจัดว่าต้องอยู่ Layer 6 อย่างตายตัว

ตัวอย่างอาการ: ข้อความแสดงเป็นตัวอักษรผิด หรือโปรแกรมอ่านรูปแบบข้อมูลไม่ได้ อาจเกี่ยวกับ encoding หรือรูปแบบที่ตกลงกัน

Layer 5 Session

จัดการการเริ่ม คงไว้ และจบการสนทนาระหว่างระบบ รวมถึงการประสานลำดับและจุดกลับมาทำงานต่อในระบบที่รองรับ แนวคิด session ในเว็บ เช่น login session มักถูกจัดการในระดับแอป ไม่ได้พิสูจน์ว่ามีโปรโตคอล Layer 5 แยกอยู่

ตัวอย่าง: ระบบประชุมหรือบริการแบบมีบทสนทนาอาจต้องรักษาบริบทของคู่สื่อสาร แต่ต้องวิเคราะห์โปรโตคอลจริงก่อนจับคู่กับ OSI

Layer 4 Transport

ใช้ port เพื่อแยก process หรือบริการบนเครื่องเดียวกัน เช่น client ใช้ source port ชั่วคราวติดต่อ destination port 443

TCPUDP
สร้าง connection และส่งเป็น byte streamส่งเป็น datagram
มี sequence, acknowledgement และ retransmissionไม่มีการรับประกันส่งถึงหรือเรียงลำดับใน UDP เอง
มี flow control และ congestion controlแอปต้องจัดการสิ่งที่ต้องการเพิ่มเอง
เหมาะเมื่ออยากได้ข้อมูลครบและตามลำดับเหมาะกับงานที่ออกแบบการส่งตามความต้องการของแอป

TCP ไม่รับประกันว่าแอปปลายทางประมวลผลสำเร็จ และ UDP ไม่ได้ “เร็วกว่าเสมอ” QUIC สามารถให้ reliable streams บน UDP ได้ เป็นตัวอย่างว่าต้องแยกคุณสมบัติ UDP ออกจากโปรโตคอลที่สร้างทับมัน

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "TCP is connection-oriented and reliable — it has a three-way handshake, sequence numbers, acknowledgements, and retransmission. UDP is connectionless and lightweight, so it's used for things like DNS, streaming, gaming, and QUIC, where the application handles reliability itself."แปล: "TCP เป็นแบบ connection-oriented และเชื่อถือได้ มี three-way handshake, sequence number, acknowledgement และการส่งซ้ำ ส่วน UDP เป็นแบบ connectionless และเบา จึงใช้กับงานอย่าง DNS, สตรีมมิง, เกม และ QUIC ที่แอปจัดการความน่าเชื่อถือเอง"

Layer 3 Network

ใช้ IP address และ routing table เพื่อเลือก next hop ถ้าปลายทางอยู่นอก subnet เครื่องมักส่งให้ default gateway เราเตอร์อ่าน IP ปลายทางแล้วส่งต่อไปยังเส้นทางที่เหมาะสม TTL ของ IPv4 หรือ Hop Limit ของ IPv6 ลดลงตามการส่งต่อ ช่วยจำกัดแพ็กเก็ตวนลูป

ตัวอย่างปัญหา: subnet mask ผิด ไม่มี default gateway หรือไม่มี route ไปปลายทาง Router อยู่ชั้น 3 เป็นหลัก แต่เครื่องจริงอาจทำ firewall หรือหน้าที่ชั้นอื่นร่วมด้วย

Layer 2 Data Link

บรรจุข้อมูลเป็น frame สำหรับส่งในลิงก์ ใช้ MAC address ใน Ethernet และมี FCS ช่วยตรวจข้อผิดพลาด Switch เรียนรู้ source MAC ที่แต่ละพอร์ต แล้วใช้ destination MAC เลือกพอร์ตส่งออก หากเป็น unknown unicast อาจ flood ภายใน VLAN

VLAN แบ่งเครือข่าย Layer 2 เป็นคนละ broadcast domain การอยู่ในอาคารเดียวกันจึงไม่ได้หมายความว่าอยู่ใน subnet หรือ VLAN เดียวกันเสมอไป Switch Layer 3 สามารถ route ได้ด้วย

Layer 1 Physical

เกี่ยวกับสัญญาณไฟฟ้า แสง คลื่นวิทยุ สาย หัวต่อ ระยะทาง และอัตราส่งข้อมูล ตัวอย่างอุปกรณ์เชิงชั้นคือ repeater และ hub ปัญหาที่พบบ่อย ได้แก่ สายหลวม ไม่มี link หรือสัญญาณรบกวน

Encapsulation และ Decapsulation

ฝั่งส่ง: ข้อมูลแอป → TCP segment หรือ UDP datagram → IP packet → frame → สัญญาณ

ฝั่งรับ: สัญญาณ → frame → IP packet → transport data → ข้อมูลแอป

แต่ละชั้นเติมข้อมูลควบคุม เช่น header และบางชั้นมี trailer ฝั่งรับอ่านและถอดตามลำดับ เราเตอร์ระหว่างทางถอด frame ขาเข้า ประมวลผล IP และสร้าง frame สำหรับลิงก์ขาออก ไม่ต้องเปิดอ่านข้อมูลแอปทุกครั้งเพื่อ route

9 การสื่อสารแบบ End to End

End to End คือการมองเส้นทางทั้งหมดระหว่างสองระบบที่สื่อสารกันจริง เช่น เบราว์เซอร์กับเว็บเซิร์ฟเวอร์ ส่วนอุปกรณ์ระหว่างทางอย่าง switch เราเตอร์ และ ISP ทำหน้าที่ช่วยส่งข้อมูลเท่านั้น แนวคิดตรงข้ามคือ hop by hop ซึ่งดูทีละลิงก์

End to endHop by hop

ตัวอย่างTCP, TLS, HTTPEthernet frame, Wi-Fi

เส้นทางเต็มของคำขอเว็บหนึ่งครั้ง

  1. ได้ที่อยู่: เครื่องมี IP, mask, gateway และ DNS server อยู่แล้ว โดยมากได้จาก DHCP
  2. แปลงชื่อ: DNS แปลง www.example.com เป็น IP
  3. เลือก next hop: ปลายทางอยู่นอก subnet เครื่องจึงส่งให้ default gateway และใช้ ARP หา MAC ของ gateway
  4. เปิดการเชื่อมต่อ: TCP ทำ three-way handshake ไปยัง port 443 จากนั้น TLS ตรวจ certificate และตกลงกุญแจ
  5. ส่งคำขอ: HTTP request ถูกเข้ารหัสแล้วห่อเป็น TCP, IP และ Ethernet frame
  6. เดินทางข้ามเครือข่าย: switch ส่งต่อตาม MAC เราเตอร์บ้านทำ NAT และเราเตอร์แต่ละตัวส่งต่อตาม IP ลดค่า TTL และสร้าง frame ใหม่
  7. ถึงเซิร์ฟเวอร์: เซิร์ฟเวอร์ถอดข้อมูลทีละชั้น และ port ส่งข้อมูลให้บริการเว็บ
  8. ตอบกลับ: คำตอบกลับมาโดยสลับต้นทางกับปลายทาง เส้นทางกลับอาจต่างจากขาไป และ NAT แปลงที่อยู่กลับให้

ทำไมจึงสำคัญ: หลักการ end-to-end บอกว่าความสามารถอย่างความน่าเชื่อถือและการเข้ารหัสควรทำที่ปลายทาง เพราะมีแต่ปลายทางที่รู้ว่างานสำเร็จจริงหรือไม่ เราเตอร์จึงเรียบง่ายได้ และ TCP กับ TLS ทำงานบน host

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "End to end means the whole path between the two systems that are communicating. TCP and TLS work end to end, so only the client and server use them. Ethernet works hop by hop, so the MAC addresses change on each link while the IP addresses normally stay the same."แปล: "End to End คือเส้นทางทั้งหมดระหว่างสองระบบที่สื่อสารกัน TCP และ TLS ทำงานแบบ end to end จึงมีแค่ client กับ server ที่ใช้ ส่วน Ethernet ทำงานแบบ hop by hop ดังนั้น MAC จึงเปลี่ยนทุกลิงก์ ขณะที่ IP โดยปกติคงเดิม"

10 TCP three-way handshake

ก่อนที่ TCP จะส่งข้อมูลของแอป ทั้งสองฝั่งต้องตกลงว่ามีการเชื่อมต่อ และแจ้งเลข sequence เริ่มต้นให้กัน three-way handshake ทำเรื่องนี้ด้วยข้อความสามครั้ง

  1. SYN: client บอกว่า ขอเชื่อมต่อ และเลข sequence ของฉันเริ่มที่ x
  2. SYN-ACK: server ตอบว่า ได้รับ x แล้ว จึงรอ x+1 ต่อไป และเลข sequence ของฉันเริ่มที่ y
  3. ACK: client ตอบว่า ได้รับ y แล้ว จึงรอ y+1 ต่อไป ตอนนี้การเชื่อมต่อเกิดขึ้นทั้งสองฝั่ง

ทำไมต้องสามครั้ง ไม่ใช่สองครั้ง

TCP ส่งข้อมูลได้สองทิศทาง แต่ละฝั่งจึงต้องได้รับการยืนยันเลข sequence ของตัวเอง ถ้ามีแค่สองครั้งจะยืนยันได้เฉพาะเลขของ client ครั้งที่สามยืนยันเลขของ server และยังช่วยให้ server ไม่สนใจคำขอเชื่อมต่อเก่าที่มาถึงช้า

เลข sequence เริ่มต้นถูกสุ่มให้เดายาก ไม่ได้เริ่มที่ศูนย์ เพื่อให้ผู้โจมตีแทรกแพ็กเก็ตปลอมเข้าการเชื่อมต่อได้ยาก นอกจากนี้ SYN และ SYN-ACK ยังส่ง option เช่น ขนาด segment สูงสุด (MSS), window scaling และ selective acknowledgement (SACK)

ความปลอดภัยและการดูแล: ห้ามมองเข้าไปในไฟเบอร์หรือพอร์ต optic เพราะแสงเลเซอร์อาจมองไม่เห็นแต่ยังทำร้ายดวงตาได้ ปิดฝากันฝุ่นไว้และทำความสะอาดหัวก่อนเสียบ ผิวหน้าหัวต่อที่สกปรกเป็นสาเหตุปัญหาไฟเบอร์ที่พบบ่อยที่สุดอย่างหนึ่ง ถ้าต้องการตรวจระดับสัญญาณ ให้อ่านกำลังแสงหน่วย dBm ด้วย show interfaces transceiver บน switch หรือ sudo ethtool -m eth0 บน Linux

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "Fiber uses light and copper uses electrical signals, so I'd use a media converter between them, then a patch cable to the switch. If the switch has an SFP slot, I'd use a module instead. Either way, I'd match the fiber type, wavelength, speed, and connector — usually LC."แปล: "ไฟเบอร์ใช้แสง ทองแดงใช้ไฟฟ้า ผมจะใช้ media converter คั่นกลาง แล้วต่อสาย LAN เข้า switch ถ้า switch มีช่อง SFP ก็ใช้โมดูลแทน ไม่ว่าแบบไหนต้องให้ชนิดสาย ความยาวคลื่น ความเร็ว และหัวต่อตรงกัน ซึ่งส่วนใหญ่เป็น LC"

12 Link aggregation: LACP และ Port Channel

Link aggregation คือการรวมลิงก์ Ethernet หลายเส้นระหว่างอุปกรณ์สองตัวให้เป็นลิงก์ตรรกะเดียว Cisco เรียกว่า EtherChannel และเรียกอินเทอร์เฟซตรรกะว่า Port-channel ผู้ผลิตอื่นเรียก LAG หรือ trunk ฝั่ง Linux เรียก bond และ Windows เรียก NIC teaming

  • แบนด์วิดท์มากขึ้น: สองลิงก์ลิงก์ละ 1 Gb/s ได้รวมสูงสุด 2 Gb/s
  • มีสำรอง: ถ้าลิงก์สมาชิกเส้นหนึ่งเสีย ลิงก์ตรรกะยังทำงานต่อบนเส้นที่เหลือ
  • STP ไม่ block: spanning tree มองทั้งชุดเป็นลิงก์เดียว จึงไม่ block สายส่วนเกิน

LACP, static และ PAgP

โหมดทำงานอย่างไร
LACP active / passiveทั้งสองฝั่งแลกข้อความ LACP เพื่อตกลงเรื่องการรวมลิงก์และจับการต่อสายผิด active เป็นฝ่ายเริ่มเจรจา ส่วน passive ตอบอย่างเดียว จึงต้องมีอย่างน้อยหนึ่งฝั่งเป็น active กำหนดใน IEEE 802.3ad ปัจจุบันคือ 802.1AX
Static (mode on)รวมพอร์ตโดยไม่เจรจา ตั้งง่าย แต่ถ้าต่อสายหรือตั้งค่าผิดอาจเกิด loop หรือทราฟฟิกหาย
PAgP (desirable / auto)โปรโตคอลเจรจาของ Cisco ถ้าใช้หลายยี่ห้อควรใช้ LACP

ทราฟฟิกถูกกระจายอย่างไร

อุปกรณ์เลือกลิงก์สมาชิกด้วยค่า hash จากที่อยู่ เช่น MAC, IP และบางครั้งรวม port ทำให้แพ็กเก็ตใน flow เดียวกันใช้ลิงก์เดียวกันและไม่สลับลำดับ ดังนั้นการดาวน์โหลดไฟล์ใหญ่ไฟล์เดียวบน 2 × 1 Gb/s ยังได้สูงสุด 1 Gb/s แต่หลาย flow รวมกันใช้ได้เต็ม 2 Gb/s

เงื่อนไขที่ต้องมี

  • ลิงก์สมาชิกทุกเส้นใช้ความเร็วและ duplex เดียวกัน
  • สมาชิกทุกเส้นตั้งค่า switchport เหมือนกัน คือ access VLAN เดียวกัน หรือเป็น trunk ที่อนุญาต VLAN และ native VLAN เหมือนกัน
  • ทั้งสองปลายตั้งเป็นชุดรวมลิงก์และใช้โหมดที่เข้ากัน
  • ทุกลิงก์ต่อไปยัง switch ตัวเดียว หรือคู่ switch ที่รองรับการรวมข้ามตัว เช่น stack, MLAG หรือ Cisco vPC

ตัวอย่าง: Cisco switch

รวมพอร์ต Gi1/0/1–2 เป็น Port-channel 1 ด้วย LACP แบบ active ตั้งให้เป็น trunk แล้วตรวจสถานะด้วย show etherchannel summary

interface range GigabitEthernet1/0/1 - 2
 channel-group 1 mode active
!
interface Port-channel1
 switchport mode trunk
!
show etherchannel summary

ตัวอย่าง: bond บนเซิร์ฟเวอร์ Debian

ติดตั้ง ifenslave แล้วสร้าง bond0 จาก eno1 และ eno2 ด้วยโหมด 802.3ad (LACP) และตรวจสถานะใน /proc/net/bonding/bond0

sudo apt install ifenslave

# /etc/network/interfaces
auto bond0
iface bond0 inet static
    address 192.168.1.50/24
    gateway 192.168.1.1
    bond-slaves eno1 eno2
    bond-mode 802.3ad
    bond-miimon 100
    bond-xmit-hash-policy layer3+4

cat /proc/net/bonding/bond0    # bond and member status

bonding บน Linux โหมด 4 (802.3ad) ต้องตั้ง LACP บน switch ด้วย ส่วนโหมด 1 (active-backup) ใช้กับ switch ใดก็ได้ แต่ให้แค่การสำรอง คือมีลิงก์เดียวที่ส่งข้อมูล อีกเส้นรอสำรอง

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "Link aggregation bundles several physical links into one logical link, like a Port-channel on Cisco, and LACP negotiates it. It gives more total bandwidth and redundancy, and spanning tree sees it as one link. Traffic is hashed per flow, so one flow can't go faster than one member link. Both ends need matching speed, VLAN settings, and LACP mode."แปล: "Link aggregation รวมลิงก์กายภาพหลายเส้นเป็นลิงก์ตรรกะเดียว เช่น Port-channel บน Cisco และใช้ LACP เจรจา ได้แบนด์วิดท์รวมมากขึ้นและมีสำรอง และ spanning tree มองเป็นลิงก์เดียว ทราฟฟิกถูกกระจายตาม flow หนึ่ง flow จึงเร็วได้ไม่เกินลิงก์สมาชิกหนึ่งเส้น ทั้งสองฝั่งต้องตั้งความเร็ว VLAN และโหมด LACP ให้ตรงกัน"

13 ถ้าเป็นเจ้าของ Server จะให้ Host เข้าถึงได้อย่างไร

ให้มองเป็นห่วงโซ่: บริการต้องทำงาน เซิร์ฟเวอร์ต้องติดต่อได้ และ firewall ทุกจุดระหว่างทางต้องเปิด port จากนั้นทดสอบจากนอกเครื่อง ไม่ใช่จากตัวเซิร์ฟเวอร์เอง

ทำทีละขั้น

  1. เปิดบริการ และตรวจว่าเริ่มเองตอนบูต
  2. ตรวจที่อยู่ที่บริการรอรับ บริการบน 127.0.0.1 รับได้เฉพาะในเครื่อง ต้องใช้ 0.0.0.0 หรือ IP ของเซิร์ฟเวอร์เพื่อให้เครื่องอื่นเชื่อมต่อได้
  3. กำหนด IP ให้คงที่ ด้วย static IP หรือ DHCP reservation เพื่อไม่ให้ที่อยู่เปลี่ยน
  4. เปิดเฉพาะ port ที่จำเป็นบน firewall ของเซิร์ฟเวอร์ เช่น 80 และ 443 ถ้าดูแลเครื่องระยะไกลต้องอนุญาต SSH ก่อน ไม่เช่นนั้นอาจเข้าเครื่องไม่ได้
  5. ทำให้มีเส้นทางเครือข่าย ถ้าอยู่ subnet เดียวกัน host ต่อได้โดยตรง ถ้าต่าง subnet ต้องมี routing และ firewall ภายในอนุญาต ถ้ามาจากอินเทอร์เน็ตต้องมี public IP พร้อม port forwarding บนเราเตอร์ หรือกฎ security group บนคลาวด์
  6. เพิ่ม DNS โดยสร้างระเบียน A หรือ AAAA ที่ชี้ชื่อไปยัง public IP
  7. เปิด HTTPS ด้วย TLS certificate เช่น จาก Let's Encrypt
  8. ทดสอบจาก client จริง ควรอยู่คนละเครือข่าย เช่น มือถือที่ใช้เน็ตมือถือ

ตัวอย่างบน Debian ด้วย nginx

ฝั่งเซิร์ฟเวอร์: ติดตั้งและเปิด nginx, ตรวจว่ารอรับที่ port ใด, อนุญาต SSH ก่อนเปิด ufw แล้วอนุญาต port 80 และ 443 ฝั่งเครื่องอื่น: ทดสอบด้วย curl และ nc

# On the server
sudo apt update && sudo apt install nginx ufw
sudo systemctl enable --now nginx
sudo ss -tlnp | grep ':80'          # Is it listening, and on which address?

sudo ufw allow OpenSSH              # Do this before enabling ufw
sudo ufw allow 80,443/tcp
sudo ufw enable

# From another host
curl -I http://192.168.1.50
nc -vz 192.168.1.50 80

ถ้าไม่มี public IPv4 เช่น เพราะ ISP ใช้ CGNAT การทำ port forwarding จะใช้ไม่ได้ ทางเลือกคือใช้ IPv6, VPS หรือเซิร์ฟเวอร์บนคลาวด์, VPN หรือบริการ tunnel

ไล่ปัญหาตามอาการ

อาการตรวจอะไร
ใช้ได้บนเซิร์ฟเวอร์แต่เครื่องอื่นเข้าไม่ได้ที่อยู่ที่บริการรอรับ และ firewall
ใช้ IP ได้แต่ใช้ชื่อไม่ได้ระเบียน DNS และ cache
ใช้ใน LAN ได้แต่จากอินเทอร์เน็ตไม่ได้port forward, กฎบนคลาวด์, ISP ปิดกั้น หรือ CGNAT ที่ทำให้ไม่มี public IP จริง

ความปลอดภัย: ไม่ควรเปิด SSH หรือฐานข้อมูลให้ทั้งอินเทอร์เน็ต ใช้ SSH key จำกัด port สำหรับดูแลระบบให้เข้าผ่าน VPN หรือ IP ที่เชื่อถือ และอัปเดตระบบสม่ำเสมอ

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: "First I'd confirm that the service is running and listening on the right address. Then I'd give the server a stable IP and open only the required ports on its firewall. For internet access, I'd set up port forwarding or a cloud security rule, add a DNS record, enable HTTPS, and test from an outside network."แปล: "อันดับแรกผมจะยืนยันว่าบริการทำงานและรอรับที่อยู่ถูกต้อง จากนั้นกำหนด IP ให้คงที่และเปิดเฉพาะ port ที่จำเป็นบน firewall ถ้าต้องให้เข้าจากอินเทอร์เน็ตก็ตั้ง port forwarding หรือกฎบนคลาวด์ เพิ่ม DNS เปิด HTTPS แล้วทดสอบจากเครือข่ายภายนอก"

คำถามสัมภาษณ์ปลายเปิด

ลองตอบเป็นภาษาอังกฤษออกเสียงก่อน แล้วค่อยเปิดดูคำตอบตัวอย่าง

เมื่อพิมพ์ URL ในเบราว์เซอร์แล้วกด Enter เกิดอะไรขึ้นบ้าง

เบราว์เซอร์แยกส่วนของ URL และตรวจ cache ถ้ายังไม่มีที่อยู่ก็ค้น DNS โดยถาม recursive resolver ซึ่งอาจไล่ถาม root, TLD และ authoritative server จนได้ระเบียน A หรือ AAAA จากนั้นเปิดการเชื่อมต่อไปยัง IP นั้นที่ port 443 ซึ่งมักเป็น TCP หรือ QUIC สำหรับ HTTP/3 แล้วทำ TLS handshake และตรวจ certificate ของเซิร์ฟเวอร์ เมื่อช่องทางปลอดภัยพร้อมก็ส่ง HTTP GET เซิร์ฟเวอร์ตอบ status code พร้อม HTML แล้วเบราว์เซอร์อ่าน HTML ดึงไฟล์อื่นอย่าง CSS และ JavaScript และแสดงผลหน้าเว็บ

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: What happens when you type a URL into the browser and press Enter?
"First the browser parses the URL and checks its caches. If it doesn't have the address, it resolves the hostname through DNS — the local resolver asks a recursive resolver, which may walk from the root to the TLD to the authoritative server, and returns an A or AAAA record. Then the browser opens a connection to that IP on port 443 — usually TCP, or QUIC for HTTP/3 — and does a TLS handshake, verifying the server's certificate. Once the secure channel is up, it sends an HTTP GET request, the server responds with HTML and a status code, and the browser parses it, fetches additional resources like CSS and JavaScript, and renders the page."
อธิบายความต่างระหว่าง TCP กับ UDP

TCP เป็นแบบ connection-oriented เปิดการเชื่อมต่อด้วย three-way handshake และรับประกันการส่งครบตามลำดับด้วย sequence number, acknowledgement และการส่งซ้ำ รวมถึงมี flow control และ congestion control ส่วน UDP เป็นแบบ connectionless ส่ง datagram โดยไม่รับประกันการส่งถึงหรือลำดับ จึงมี overhead น้อยกว่า ผมจะเลือก TCP สำหรับหน้าเว็บหรือการโอนไฟล์ และ UDP สำหรับ DNS เสียงหรือวิดีโอแบบเรียลไทม์ หรือเกม ที่ความหน่วงต่ำสำคัญกว่าการได้ทุกแพ็กเก็ต

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: Explain the difference between TCP and UDP.
"TCP is connection-oriented. It sets up a connection with a three-way handshake and guarantees reliable, in-order delivery using sequence numbers, acknowledgements, and retransmission, plus flow and congestion control. UDP is connectionless — it just sends datagrams with no delivery or ordering guarantees, so it has less overhead. I'd choose TCP for things like web pages or file transfers, and UDP for DNS queries, real-time voice or video, or games, where low latency matters more than every packet arriving."
switch กับ router ต่างกันอย่างไร

switch ส่งต่อ frame ภายในเครือข่ายท้องถิ่นโดยใช้ MAC ซึ่งเป็น Layer 2 ส่วน router ส่งต่อ packet ระหว่างเครือข่ายโดยใช้ IP และ routing table ซึ่งเป็น Layer 3 ในทางปฏิบัติ switch Layer 3 ทำได้ทั้งสองอย่าง และเราเตอร์บ้านมักรวม router, switch, Wi-Fi access point, DHCP และ NAT ไว้ในเครื่องเดียว

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: What is the difference between a switch and a router?
"A switch forwards frames within a local network using MAC addresses — that's Layer 2. A router forwards packets between different networks using IP addresses and a routing table — that's Layer 3. In practice, a Layer 3 switch can do both, and a home router usually combines a router, a switch, a Wi-Fi access point, DHCP, and NAT in one box."
subnet mask คืออะไร และแบ่ง subnet ไปทำไม

subnet mask บอกว่าส่วนใดของ IP เป็นเครือข่ายและส่วนใดเป็น host เช่น /24 หรือ 255.255.255.0 หมายถึง 24 บิตแรกเป็นเครือข่าย การแบ่ง subnet ช่วยแยกเครือข่ายใหญ่เป็น broadcast domain ที่เล็กลง ทำให้ประสิทธิภาพดีขึ้น ใช้นโยบายความปลอดภัยได้ง่ายขึ้น และใช้ที่อยู่ได้คุ้มค่ากว่า

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: What is a subnet mask, and why do we use subnets?
"A subnet mask tells you which part of an IP address is the network and which part is the host. For example, /24 or 255.255.255.0 means the first 24 bits are the network. Subnetting lets us split a big network into smaller broadcast domains, which improves performance, makes security policies easier to apply, and uses address space more efficiently."
NAT คืออะไร และเป็นฟีเจอร์ด้านความปลอดภัยหรือไม่

NAT หรือ Network Address Translation เปลี่ยนที่อยู่ขณะทราฟฟิกผ่านเราเตอร์ โดยมากเพื่อให้หลายเครื่องที่ใช้ private IPv4 ใช้ public address เดียวกัน NAT ซ่อนที่อยู่ภายในก็จริง แต่ไม่ใช่ firewall ความปลอดภัยควรมาจากกฎ firewall ที่ถูกต้อง ไม่ใช่พึ่ง NAT อย่างเดียว

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: What is NAT, and is it a security feature?
"NAT — Network Address Translation — rewrites addresses as traffic passes through a router, usually so that many devices with private IPv4 addresses can share one public address. It does hide internal addresses, but it isn't a firewall. Security should come from proper firewall rules, not from NAT alone."
ผู้ใช้บอกว่าอินเทอร์เน็ตใช้ไม่ได้ จะไล่ปัญหาอย่างไร

ผมจะไล่ทีละชั้น เริ่มจากการเชื่อมต่อกายภาพ เช่น สาย ไฟ link หรือการต่อ Wi-Fi แล้วตรวจว่าเครื่องได้ IP, subnet mask และ gateway ถูกต้อง ถ้าได้ 169.254 แสดงว่าน่าจะมีปัญหา DHCP ต่อมา ping gateway แล้ว ping public IP เพื่อดูว่าขาดตรงไหน ถ้าใช้ IP ได้แต่ใช้ชื่อไม่ได้ น่าจะเป็น DNS และถ้าเข้าไม่ได้แค่บางเว็บ ผมจะตรวจ port, firewall, certificate และสิ่งที่แอปตอบกลับมา

ตอบสัมภาษณ์เป็นภาษาอังกฤษ: A user says "the internet is down." How would you troubleshoot it?
"I'd go layer by layer. First, check the physical connection — the cable, link light, or Wi-Fi association. Then check whether the device has a valid IP address, subnet mask, and gateway — a 169.254 address would suggest a DHCP problem. Next, ping the gateway, then a public IP, to see where connectivity stops. If IPs work but names don't, it's likely DNS. Finally, if a specific site fails, I'd check the port, the firewall, the certificate, and what the application actually returns."
